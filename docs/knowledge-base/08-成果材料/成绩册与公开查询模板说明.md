## 样例结构

PDF/成绩册 HTML 共 7 页：封面、赛事信息与名单、小组排名、小组逐场结果、淘汰进程、最终名次、双打空白结果核对表。样例只有完整男单数据，其他四项标签不等于已有数据。

模拟数据为 8 人、A/B 两组、4 块场地、16 场比赛：12 场循环赛、2 场半决赛、三四名赛和决赛。小组胜场为 3/2/1/0，没有退赛和同分案例，因此不能把样例简单排序当作完整排名算法。

视觉采用白底、深蓝标题、青绿分隔和少量金色强调，不冒用学校官方配色、校徽、公章或签名。所有姓名、代表队、日期和成绩均标记模拟。

## 真实系统集成要求

- 静态 HTML 未来拆成 React 组件，但数据必须来自服务端批准的公开白名单和统一锁定快照。
- 排名只由领域/服务端算法计算，文档渲染层不得复制另一套排名逻辑。
- 未锁定、存在争议或缺少必要比赛时只能生成明显标记的草稿。
- HTML 输入转义；双打两名成员完整显示，长姓名不裁切。
- PDF 由受控服务端任务绑定授权赛事与快照生成，不接受任意 URL 去访问内部资源。
- 表格跨页重复表头、行不随意断裂；五单项和页码随真实数据动态生成。
- 只有真实查询 URL 存在并验证后才生成二维码。
- 导出文件使用版本化文件名；更正后生成新版本，不覆盖旧 PDF。

## 数据和版式口径

逐局分数固定从 A 方视角记录，胜者单列；未打第三局使用“—”，不写 0:0。WO/RET 等显示真实已发生比分加结局标签，不补满分。公开页和公开版 PDF/Excel 共用同一字段白名单。

手机成绩册使用自然流式布局；复杂表格仅容器内横向滚动。公开页 375px 起使用卡片，平板/电脑可用两列；触控区至少 44 CSS 像素，状态不得只靠颜色。

## 外部样例已有检查及边界

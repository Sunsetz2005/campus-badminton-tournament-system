# 公开赛程与成绩中心：页面与状态清单

## 1. 任务拆分与阶段边界

| 编号 | 内容 | 当前状态 |
|---|---|---|
| UI-01-A | 参考核验、现状审计、界面规范和任务拆分 | 本轮完成 |
| UI-01-B | 每日赛程与比赛详情的隔离预览 | 已实现；每日赛程视觉修正待用户确认 |
| UI-01-C | 接入真实公开赛程与比赛详情服务 | 未实现，依赖后续权威服务 |
| UI-01-D | 接入对阵、排名、最终名次和成绩册 | 未实现，依赖后续业务阶段 |

UI-01 不修改裁判端、规则引擎、数据库、认证或权限，不改变“阶段 3 收尾、未经授权不进入阶段 4”的门禁。

## 2. 当前公开能力

- 页面只有 `/public`，并固定读取 `phase-1-demo`。
- 接口只有 `GET /api/public/tournaments/[slug]`，只返回 `PUBLISHED` 赛事和白名单字段。
- 当前字段包含赛事 `slug/name/timezone/status`，项目、阶段、比赛 `code/lifecycleStatus/outcomeType/verificationStatus/scheduledAt`、场地、A/B Entry 显示名和逐局比分。
- 当前缺少比赛详情路由、双打成员、代表队公开策略、实际开始/结束时间、版本/更新时间、冻结规则摘要、公开更正标记和服务端赛程顺序。
- 当前只检查赛事级 `PUBLISHED`，没有逐场发布状态或权威发布快照；现有查询会返回该赛事下全部嵌套比赛，不能直接作为真实公开赛程边界。
- 姓名与代表队公开范围仍待组织者确认；现有端点无条件返回 `Entry.displayName/code`，只对当前匿名模拟种子可接受，不能原样接到真实参赛者名单。

因此现有 `/public` 只能称为“公开白名单骨架”，不能称为完整公开赛程与成绩中心。

## 3. 五个导航入口

| 入口 | 建议正式路由 | UI-01-B | 真实开放条件 |
|---|---|---|---|
| 每日赛程 | `/public/[tournamentSlug]/schedule` | 可操作模拟预览 | 权威赛程、服务端排序、公开字段和版本信息 |
| 对阵与晋级 | `/public/[tournamentSlug]/bracket` | 显示“暂未开放” | 权威签表、锁定结果和更正影响处理 |
| 小组排名 | `/public/[tournamentSlug]/standings` | 显示“暂未开放” | 排名服务、排序/抽签解释与正式结果 |
| 最终名次 | `/public/[tournamentSlug]/rankings` | 显示“暂未开放” | 正式排名和实际排位赛配置 |
| 成绩册 | `/public/[tournamentSlug]/results-book` | 显示“暂未开放” | 真实版本化文件、生成时间、正式状态和替代关系 |

未实现入口不提供可点击的假页面、假排名或假下载。模拟 PDF 只能单独标明“查看模拟模板”。

## 4. 路由与筛选

### 4.1 正式页面

```text
/public/[tournamentSlug]/schedule
/public/[tournamentSlug]/matches/[matchCode]
```

`tournamentSlug` 沿用当前公开赛事标识，不暴露数据库 UUID。比赛详情同时校验赛事、比赛关系和权威发布快照；不存在、未进入发布快照或不属于该赛事的比赛统一返回公开 404。赛事级 `PUBLISHED` 不能替代逐场发布边界。

UI-01-C 开始前，服务端须把 `tournamentSlug` 和 `matchCode` 限定为有长度上限的安全路径字符集，统一大小写/规范化规则，并保证发布后稳定；无效输入直接返回公开 404，不回显内部标识。

### 4.2 可分享 query

```text
?date=YYYY-MM-DD
&competition=<公开项目代码>
&stage=<公开阶段代码>
&court=<公开场地代码>
&lifecycle=<逗号分隔的 MatchLifecycleStatus>
&verification=<逗号分隔的 VerificationStatus>
&outcome=<逗号分隔的 MatchOutcomeType>
&q=<获准公开的姓名、编号、别名或代表队>
```

- `date` 按赛事时区解释，不按访问设备时区解释；不得写死参考站的 2026-09-21。
- 缺省日期只能从赛事已发布日期中确定；无效日期显示错误和可返回的有效日期，不静默换日。
- 页面可以把三类状态合并成一个分组筛选控件，但 URL 保留 `lifecycle/verification/outcome` 三个维度。每个维度内部按 OR 匹配，三个维度之间按 AND 匹配；多选值去重并按稳定顺序写成逗号列表，“全部”通过移除该参数表达。
- 切换日期不自动清除其他条件；条件无匹配时进入“无筛选结果”，继续显示所选条件。
- 未知或失效条件显示“筛选项已失效”，由用户明确移除。
- `q` 只搜索服务端允许公开的字段；姓名未获批准时只搜索公开编号或别名。
- 详情页返回赛程时恢复原 query；不接受未校验的任意 `returnTo` 外部地址。

### 4.3 UI-01-B 隔离预览

建议入口：

```text
/public/preview/[tournamentSlug]/schedule
/public/preview/[tournamentSlug]/matches/[matchCode]
```

- 只有非生产环境且显式开启 `ENABLE_PUBLIC_UI_PREVIEW=true` 时可访问，否则 404。
- 不加入正式导航，不替换当前 `/public`，增加 `noindex,nofollow`。
- 页面首屏始终显示“模拟数据／界面预览”。
- 只读独立虚构 fixture，不读取或修改数据库、种子、认证会话、裁判接口或生产配置。
- 预览展示类型与未来公开 DTO 对齐，但通过适配器隔离，不让组件依赖 Prisma 对象或规则引擎聚合。
- 使用 CSS Module 或严格功能前缀，避免覆盖并行修改中的裁判全局样式。

## 5. 每日赛程

### 5.1 页面顺序

1. 赛事名称、举办日期、公开场馆/公告、赛事时区和数据更新时间；没有字段时省略，不编造。
2. 五入口二级导航。
3. 日期选择。
4. 项目、状态、阶段、场地和公开搜索。
5. 已选条件及清除入口。
6. 结果数量、最后成功同步时间和过期提示。
7. 服务端顺序的比赛列表。
8. 加载、空、失败或过期状态。

桌面把项目、比赛进度、场地、阶段、搜索和“更多”放入同一扫描带。390 手机把四个主筛选排为 2×2，搜索保持可见；结果确认、特殊结果和预览场景进入“更多筛选”。关闭后焦点返回触发按钮，刷新或自动取数不能清除条件。

### 5.2 时间语义

设计需要区分固定时间、预计时间、延后、前序比赛结束后、时间待定和实际开始时间。当前公开 DTO 只暴露可空的 `scheduledAt`，不能表达完整语义；Prisma 虽有 `startedAt/endedAt`，但当前 `endedAt` 会在待提交、提交、确认或重开相关投影更新时重写，尚不能直接解释成稳定的公开“实际结束时间”。UI-01-B 可用明显标注的模拟字段检查布局；UI-01-C 必须先定义可信时间投影语义，再由权威排程/比赛服务提供，前端不得按当前时间或比分猜测。

目标 DTO 还需提供赛事时区自然日 `scheduleDate` 和 `timeType`：有日期但没有精确时间时显示“时间待定”或“前序比赛结束后”；没有 `scheduleDate` 的场次不硬塞进任一天，归入明确的“待排期”集合。`scheduledAt`、场地或任一方为空时分别显示“时间待定”“待定场地”“待定”，不能伪造占位比分或名称。

### 5.3 比赛行或卡片

至少显示：比赛编号、项目、阶段/组别、场地、时间语义、A/B 双方、获准公开的代表队、双打成员、总局分、逐局比分、比赛进度、结果有效性、异常结局和详情入口。

- A/B 身份和行序稳定，不因领先或获胜而交换。
- 比分刷新不改变服务端赛程顺序；前端不自行按“进行中优先”重排。
- 双打成员允许换行，不以不可访问的省略号隐藏第二人。
- 未进行局不渲染为 0:0；只有已创建的当前局才可显示真实 0:0。

## 6. 比赛详情

公开详情不渲染加减分、撤销、更正、提交、接管或任何内部操作。

展示顺序：

1. 返回赛程、比赛编号、项目、阶段、组别、场地和时间；
2. 比赛进度、结果有效性和异常结局三维状态；
3. A/B 双方及双打完整成员；
4. 总局分与动态逐局比分；
5. 当前局、计划/实际时间、最后同步时间；
6. 冻结规则的公开摘要；
7. 公开更正标记；
8. 仅经配置批准的裁判公开显示名。

局列由冻结规则的 `bestOf` 决定，不固定三局。未进行的局显示“—”或“未进行”；总局分和权威胜方由服务端投影提供，UI 不自行判胜。特殊结局保留真实已发生比分，不补满目标分。

规则摘要只显示赛制局数、目标分、净胜分、封顶分等允许公开的信息。三个内置 profile 仍是演示配置，未获赛事采纳前不能称为正式规程。

## 7. 三维状态映射

公开端不得把比赛进度、结果是否正式和异常结局压成一个“已结束”。

### 7.1 比赛进度：`MatchLifecycleStatus`

| 领域值 | 公开标签 |
|---|---|
| `SCHEDULED` | 已排期 |
| `READY` | 待开赛 |
| `IN_PROGRESS` | 进行中 |
| `SUSPENDED` | 已暂停 |
| `ENDED_PENDING_SUBMISSION` | 已结束待提交 |
| `SUBMITTED` | 已提交 |

### 7.2 结果有效性：`VerificationStatus`

| 领域值 | 公开标签 | 正式性 |
|---|---|---|
| `UNVERIFIED` | 未复核／临时 | 不能作为正式晋级依据 |
| `PENDING_REVIEW` | 待复核 | 临时结果 |
| `LOCKED` | 正式结果 | 可由权威业务服务用于正式排名 |
| `DISPUTED` | 争议结果 | 不升级为正式结果 |
| `SUPERSEDED` | 已被新版本替代 | 不作为当前结果 |

赛前可省略结果标签或显示“尚无结果”，不能让“未复核”看起来像异常。当前命令服务只会投影 `UNVERIFIED/PENDING_REVIEW/LOCKED`；`DISPUTED/SUPERSEDED` 在 UI-01-B 只是目标态模拟。UI-01-C 只有在经隐私过滤的结果修订/更正公开投影能够真实产生这些状态后才开放它们；“更正处理中”必须是单独的公开更正状态，不能拿 `DISPUTED` 代替。

### 7.3 异常结局：`MatchOutcomeType`

| 领域值 | 公开标签 |
|---|---|
| `NORMAL` | 正常完赛 |
| `WO` | WO／弃权 |
| `RET` | 退赛 |
| `DSQ` | 取消资格 |
| `ABANDONED` | 比赛中止 |
| `BYE` | 轮空 |

内部 `reason` 可能含伤病、纪律或处理信息，默认不公开。若以后需要解释，新增经审核的 `publicOutcomeNote`，不能直接复用内部原因。当前领域没有 `CANCELLED`；不得把 `ABANDONED` 冒充“取消”。

## 8. 目标公开字段白名单

| 类别 | UI-01-C 需要的公开字段 |
|---|---|
| 赛事 | slug、公开名称、赛事时区、发布日期范围、公开场馆/公告、数据更新时间 |
| 比赛身份 | matchCode、scoreVersion（现有 `Match.version`）、单调 projectionRevision、项目/阶段/组别公开代码与名称、服务端赛程顺序 |
| 时间与场地 | 赛事时区 `scheduleDate`、时间类型、计划时间、公开前序比赛编号、可信实际开始/结束时间、可空场地公开代码/名称 |
| 双方 | 可空 A/B；由隐私发布投影给出的公开编号、批准的名称/别名、成员和代表队 |
| 比分 | 当前局、逐局比分、局是否完成、总局分、权威胜方 |
| 状态 | lifecycleStatus、verificationStatus、outcomeType、公开更正标记 |
| 规则 | bestOf、目标分、净胜分、封顶分和批准公开的规则名称 |
| 发布与同步 | 发布快照/逐场发布边界、scoreVersion、单调 projectionRevision、可选强 ETag、数据更新时间、服务端响应时间 |
| 裁判 | 仅配置批准的公开显示名，不含账号资料 |

默认禁止返回或先下发后用 CSS 隐藏：数据库/内部 ID、学号和联系方式、登录账号/角色/会话/token/设备/租约、医疗或纪律细节、原始命令/事件/审计、更正理由、未进入权威发布快照的比赛和草稿赛程。姓名、成员和代表队必须由隐私发布投影决定；不能先发送真实值再靠 CSS 隐藏。

## 9. 页面数据状态

| 状态 | 每日赛程 | 比赛详情 |
|---|---|---|
| 初次加载 | 保留页头和筛选骨架，列表 `aria-busy`；不显示“暂无比赛” | 保留返回入口和详情骨架 |
| 当日无赛程 | “该日期暂无已发布赛程”，提供其他有效日期 | 不适用 |
| 无筛选结果 | 明确“有赛程，但当前条件无匹配”，显示条件和清除入口 | 不适用 |
| 请求失败且无旧数据 | “赛程加载失败”及重试 | “比赛详情加载失败”及重试 |
| 请求失败但有旧数据 | 保留最后成功数据，显示“连接中断／数据可能过期”和最后同步时间 | 同左 |
| 数据过期 | 文字状态常驻并允许手动刷新 | 同左 |
| 公开 404 | 不暴露草稿或跨赛事信息 | “比赛不存在或尚未公开”，返回赛程 |
| 未开放功能 | 显示“暂未开放”，无假链接 | 不适用 |

错误不得把比分清零、删除已有卡片、伪装为空列表或显示随机增长。自动刷新保留导航、筛选、滚动位置和键盘焦点。

## 10. 时区、更新与版本安全

- `Tournament.timezone` 是日程边界来源；当前建议值为 `Asia/Shanghai`，多时区需求后续再议。UI-01-C 必须在服务端按 IANA 时区标识校验；缺失或无效时 fail closed，不按设备时区或 UTC 猜测日期。
- `date` 表示赛事时区中的自然日；设备时区不能让比赛悄悄跨日。
- “数据更新时间”是服务端数据最后变化时间；“最后同步时间”是浏览器最后成功取得响应的时间。失败请求不能更新后者。
- 现有 `Match.version` 只随计分命令推进，目标公开 DTO 将其明确命名为 `scoreVersion`，只用于防止比分和比赛领域状态回退。
- 排期、场地、公开名称或更正标记等变化未必推进 `scoreVersion`；整个公开响应必须另有单调 `projectionRevision`。客户端只用该修订号比较整对象，不能拿 `scoreVersion` 保护所有元数据。
- 强 ETag 只能用于相等判断和 `If-None-Match` 缓存再验证，不能比较新旧或替代单调修订号。若真实服务暂时只有 ETag，客户端不做跨响应字段级合并，只按请求序号或 AbortController 丢弃迟到响应后整体替换。
- 切换筛选时取消旧请求或使用请求序号，迟到响应不能覆盖新条件。
- UI-01-B 不增加 WebSocket、SSE、随机比分动画或并行实时架构；UI-01-C 沿用届时已有的受控公开取数方式。

## 11. 移动端与可访问性

- 375/390 下页面根节点不得横向溢出；桌面表格在窄屏改为比赛卡。
- 对阵树和必要大表格只允许在有提示的局部容器横向滚动。
- 双打成员和长姓名完整换行；主要触摸目标以 48 CSS px 为设计目标，紧凑结果列表不低于 40 CSS px，仍待真机触控验收。
- 状态同时使用文字和结构，不只依赖颜色。
- 筛选面板支持键盘关闭、可见焦点、正确按钮标签和焦点返回。
- 自动刷新不抢焦点、不持续闪烁。
- 375、390、768、1024、1440 的浏览器模拟截图与真机验收分开记录；未测对比度前不声称符合特定标准。

## 12. 数据依赖与实施顺序

### UI-01-B：隔离预览

独立虚构 fixture 覆盖：五个项目、单双打、长姓名、不同局数；赛前、进行中、暂停、结束待提交、待复核、正式、争议、被替代和特殊结局；固定、预计、延后和前序比赛后；加载、空赛程、无筛选结果、失败、过期和详情 404。所有状态确定性可选，不用随机比分。

### UI-01-C：真实赛程与详情

开始前必须具备：权威发布快照或显式逐场发布边界、权威赛程顺序、比赛详情公开投影、姓名/成员/代表队隐私发布策略、经隐私过滤的结果修订/公开更正投影、`scheduleDate/timeType`、`scoreVersion`、单调 `projectionRevision`、更新时间、可信实际开始/结束时间、IANA 时区校验、稳定安全的公开路径段、公开规则摘要与更正标记。服务端可另发强 ETag 供缓存再验证。建议在现有公开服务边界内新增：

```text
GET /api/public/tournaments/[slug]/schedule
GET /api/public/tournaments/[slug]/matches/[matchCode]
```

页面不得直接查询 Prisma，也不得复用受保护的裁判状态接口。

### UI-01-D：其余结果入口

对阵与晋级依赖权威签表和锁定结果；小组排名依赖可解释排名服务；最终名次依赖实际排位赛配置；成绩册依赖锁定一致快照、真实文件、版本、正式状态和替代关系。

## 13. UI-01-B 验收清单

- 预览门禁关闭时返回 404；生产环境保持整站可用，但预览路由即使设置开关也返回 404。
- 页面始终可见“模拟数据／界面预览”，不含真实学生资料或参考站赛事数据。
- 日期、项目、阶段、场地、状态和搜索可操作并在刷新后恢复。
- 列表进入详情再返回后，原筛选完整恢复。
- A/B 顺序稳定；动态局数、总局分、逐局比分和未进行局正确。
- 三维状态互不替代，未锁定结果不显示为正式。

## 14. UI-01-B 实际实现（2026-09-20）

UI-01-B 已按用户确认实现为隔离预览，不替换正式 `/public`，也没有接入数据库、认证会话、裁判状态 API、真实学生资料或生产公开接口。

### 14.1 路由与门禁

- `/public/preview/autumn-campus-2026/schedule`
- `/public/preview/autumn-campus-2026/matches/[matchCode]`
- 非生产环境仍需显式 `ENABLE_PUBLIC_UI_PREVIEW=true`；关闭时返回 404。
- 生产环境无论开关值如何均返回 404，但不会因为误配预览开关而拒绝整站启动。
- 预览 metadata 使用 `noindex,nofollow`；错误赛事和未知比赛不回退到其他数据，未知比赛浏览器实测 HTTP 404。

### 14.2 组件和 Props 边界

```text
PublicResultsShell
├─ PublicSchedulePreview
│  └─ ScheduleMatch → EntryIdentity / MatchScore / StatusCluster
└─ MatchDetailPreview
   └─ EntryIdentity / MatchScore / StatusCluster

ScoringWorkbench
└─ CourtConsole + ActionButton / ResourceState / StatusBadge
```

- `PublicResultsShellProps` 只接收 `activeSection`、公开赛事 DTO 和子内容。
- `ScheduleMatchProps` 只接收公开比赛 DTO、详情地址和 `table-row | card` 展示模式。
- `MatchScoreProps` 只接收公开逐局比分、总局分、A/B 名称和权威胜方；不自行判胜。
- `StatusClusterProps` 只映射比赛进度、结果有效性、异常结局和公开更正四组展示字段。
- `ActionButtonProps` 继承原生 button 属性，并用 `loading/loadingLabel/size/variant` 表达等待和视觉层级。
- `ResourceStateProps` 用 `tone/title/description/eyebrow/action` 统一加载、空、错误、过期和 404 状态。
- 公开组件没有加分、撤销、更正、接管、租约或控制 token Props；裁判工作台没有引入公开 fixture。

### 14.3 已实现的边界状态

- 连续快速修改筛选使用乐观查询参数基线，不会因 RSC 导航延迟丢失前一个条件。
- 区分加载、当日无赛程、无筛选结果、首次失败、保留旧数据的过期状态和详情 HTTP 404。
- 覆盖五个项目、单双打、长姓名、固定/预计/延后/前序比赛后/待定时间、单局/三局/五局、WO/RET/DSQ/ABANDONED/BYE。

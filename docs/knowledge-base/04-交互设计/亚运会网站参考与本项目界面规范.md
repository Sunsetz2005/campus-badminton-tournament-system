## 4. 本项目当前代码现状

当前公开页面为 `/public`，服务端固定读取 `phase-1-demo`。`GET /api/public/tournaments/[slug]` 只检查赛事级 `PUBLISHED`，然后通过 Prisma `select` 返回该赛事下的比赛；当前没有逐场发布状态或权威发布快照，不能把赛事已发布等同于全部赛程均可公开。目前已有赛事名称/时区、项目、阶段、比赛编号、计划时间、场地、生命周期、结局、复核状态、A/B Entry 显示名和逐局比分。

当前页面仍只是匿名模拟骨架，没有：

- 携带赛事公开标识的页面路由；
- 日期、项目、阶段、场地、状态和搜索筛选；
- 查询参数恢复与比赛详情路由；
- 双打成员、代表队、动态局数规则摘要；
- 可信的实际开始/结束时间、比分版本、公开投影修订号和数据更新时间；
- 逐场发布边界，以及姓名、成员和代表队的隐私发布投影；
- 加载失败、数据过期、无筛选结果和详情不存在等完整状态；
- 排名、晋级和正式成绩册服务。

现有 `Entry.displayName/code` 无条件进入公开投影，只能用于当前匿名模拟种子；在没有公开许可和隐私投影前，UI-01-C 不得把该端点原样接到真实名单。现有受保护的 `/api/matches/[matchCode]/state` 包含裁判控制相关信息，公开详情页也不得复用。裁判工作台、场地图、规则引擎及全局样式正在另一个会话中并行修改；UI-01 本轮不触碰这些文件。

## 5. 本项目采用的设计方向

UI-01-A 原先记录了多来源的方向探索。2026-09-20 的“每日赛程”视觉修正已由用户收窄参考权威：

- 唯一主参考是 `artifacts/ui-01/user-provided-concepts/concept-01-guangdong-composite.png`，与本轮原附件 SHA-256 一致；
- 只采用其图 1 的桌面“每日赛程”和图 2 的手机“每日赛程”区域；
- 不从图 3 比赛详情、概念图二或之前的多图融合方向取导航、颜色或布局；
- 只提炼宽内容区、紧凑页头、桌面扫描表格、手机重组卡片和双方/逐局比分对齐，不复制其品牌、校徽、队徽、口号或数据。

建议公开导航为：

`每日赛程｜对阵与晋级｜小组排名｜最终名次｜成绩册`

首个实现批次只包含每日赛程和比赛详情。未接入权威服务的入口显示“暂未开放”，不提供假下载、假跳转或点击后假成功。

### 5.1 三端边界

| 界面 | 核心目标 | 不得混入 |
|---|---|---|
| 公开端 | 快速查询何时、何地、谁对谁、比分和正式结果 | 计分、撤销、租约、内部审计和账号资料 |
| 管理端 | 录入、编排、冲突处理、复核和发布 | 为外观一致而牺牲后台效率或绕过服务端权限 |
| 裁判端 | 稳定 A/B、大比分、发接发/位置、换边、连接和写权限 | 公众信息列表、宣传布局或面向观众的重新排序 |

三端可以共享色彩、字体、图标规范和状态用语，但不能共享会引入权限或写接口的数据组件。

### 5.2 每日赛程

- 桌面使用可扫描表格，窄屏使用比赛卡；两者读取同一展示模型，不维护两套业务规则。
- 日期、项目、阶段、场地、状态和获准公开的搜索条件写入 URL 并可刷新恢复。
- 手机首屏只保留日期、项目、状态，其他条件进入“更多筛选”；已选条件和清除入口始终可见。
- 每场显示比赛编号、项目、阶段/组别、场地、时间语义、A/B 双方、代表队、总局分、逐局比分、比赛进度、结果有效性和异常结局。
- 双打两名成员完整换行显示，不以不可访问的省略号隐藏第二人。
- 顺序只由服务端赛程决定；比分刷新不能交换 A/B、把赢家移到首行或让卡片随机跳动。

### 5.3 比赛详情

按“场次信息 → A/B 双方 → 总局分/逐局比分 → 三维状态 → 时间/规则/同步信息”的顺序展示。局列根据冻结规则动态生成，未进行的局显示“—”或“未进行”，不补造 21:0、15:0 或 0:0。

比赛进度、结果有效性和异常结局分别呈现，不能全部压成“已结束”。裁判姓名只在赛事组织者明确允许时公开；联系方式、伤病原因、内部更正理由、原始命令和审计日志永不进入公开响应。

### 5.4 响应式与可用性

- 375/390 宽度下页面根节点不得横向溢出；日期带、对阵树或必要大表格只能在带提示的局部容器内横向滚动。
- 主要触摸目标以不小于 48 CSS px 为设计目标。
- 状态必须有文字，不只靠颜色；筛选面板支持键盘关闭、焦点返回和错误重试。
- 自动刷新不得丢失导航、筛选、A/B 身份、滚动位置或焦点。
- 浏览器模拟截图只能写“模拟视口检查”，不能写“真机通过”。

## 6. 视觉、版权与图像生成边界

视觉使用深海军蓝、清晰蓝、浅蓝、白和冷灰建立高校赛事气质；具体色值、对比度和焦点样式要在预览实现后实测，本文不声称已符合某项可访问性标准。

不得复制亚运会名称、标识、吉祥物、赞助商、摄影、人物、旗帜、赛事数据或源代码，也不得复用概念图中的学校标识和虚构资料。`image-to-code` 只用于设计确认后的视觉翻译，不把截图裁切成页面资产。

未来确需 `imagegen` 时，只允许生成不承载功能的原创位图，例如低对比羽毛球轨迹、抽象球场线条或背景纹理。不得用它生成或仿制 logo、校徽、队徽、人物头像、状态图标、操作图标或含关键赛事文字的图片；功能图标优先采用代码原生 SVG/CSS。关闭装饰图片后，全部信息和操作仍须可用。

## 7. 不采用或暂缓

- 不采用参考站的多项目巨型导航、收藏、语言、访客时区切换、NOC 旗帜和奖牌筛选。
- 不因参考站使用 hash 路由而改变本项目路由体系。
- 不采用概念图中的人物照片、自动赛况文字和技术统计，除非以后出现已授权的权威数据源。
- 不为排名、晋级、最终名次和成绩册另写前端算法或模拟正式结果。
- 不把未确认的比赛升级为正式晋级依据，不制作随机比分增长、假实时动画或假 PDF 下载。
- 不把全部比赛固定为三局，不为未举行的排位赛捏造精确名次。
- 手机底部全站导航、完整对阵树和多时区能力暂缓到相应业务服务具备后再决定。

## 9. 后续第一小步

设计确认后只实现每日赛程和比赛详情的隔离预览：使用独立虚构 fixture、显式预览标识和非生产门禁；不改数据库、种子、认证、规则引擎、裁判接口或正式 `/public`。完成可操作筛选、详情导航、六类页面状态和 375/390/768/1024/1440 浏览器模拟检查后停止。真实赛程、排名、晋级和成绩册只在相应权威服务具备后接入。

## 10. 设计确认后的实现结果

UI-01-B 已完成上述第一小步：独立预览路由、虚构公开 DTO、可分享筛选、每日赛程、比赛详情、动态局数、三维状态、加载/空/错误/过期/404 和响应式双形态均已实现。视觉采用深海军蓝、白、冷灰和克制的绿/琥珀状态色，与裁判台共享字体、焦点、按钮和状态语言，但公开组件与受保护写入路径保持隔离。

四张 ImageGen 图只用于布局探索，未作为产品背景或功能图标；页面实际实现为 React/CSS。实际项目截图位于 `artifacts/ui-01/project-preview/`，生成设计参考位于 `artifacts/ui-01/generated-design-references/`，两者用途和哈希已在证据 README 中分开记录。

当前结论仍是“隔离模拟预览”，不是正式公开查询系统。没有实现真实发布快照、姓名授权、排名、晋级、最终名次、成绩册或实时推送，也没有声称完成真机和完整 WCAG 验收。

本轮只修正每日赛程，不改比赛详情、正式 `/public`、数据库、权限、计分/排名规则或 API 契约。最终代码参数如下：

| 区域 | 最终参数/行为 |

实际读图迭代为三轮：第一轮改整体比例和双端信息结构，第二轮压缩桌面行高与手机首屏，第三轮完成 820 两列卡片并在终检中修正手机进度徽标、日期裁切和 820 根级溢出。修改前、三轮过程和最终图位于 `artifacts/ui-01/daily-schedule-visual-fix/`。

仍有有意保留的差异：本轮没有扩大到公开站全局品牌页头，也没有在无授权资产时伪造校徽/队徽；代表队层级与参考的徽标化效果仍不同。当前结果待用户确认，不视为已获视觉验收。

# 场地化裁判工作台

2026-09-20 按用户需求把 `/officiating/[matchCode]` 改造为「先看场地、再看比分」的执裁界面。
本文记录采用的结构、坐标模型与视觉约定。

## 1. 页面阅读顺序

```text
紧凑比赛信息（项目/场地/局数/网络/控制/同步/服务器版本）
  → 横向模拟场地（球网竖直居中，左右各一方，每方两个逻辑发球区）
  → 一行三个按钮：左侧换位 — 换边 — 右侧换位
  → 大比分（双方名称 + 等宽数字，跟随画面左右队伍）
  → 双方加分与更正：左方+1 / 更正−1 ‖ 更正−1 / 右方+1
  → 精简状态：下一次发接发、写入状态说明、全名展开
  → 折叠抽屉：暂停、详细更正、异常结果、接管、视角、事件记录、提交与复核
```

只保留**一个**主「换边」按钮。抛币与首发/首接设置走开局流程，开赛后不再占据首屏。

## 2. 坐标与状态的分离

四类坐标严格分开，互不混用：

| 概念 | 存放位置 | 说明 |
|---|---|---|
| `side`（A/B 稳定身份） | `MatchState.servingSide`、`score` 等 | 不因换边或翻转改变 |
| `logicalCourts`（逻辑 R/L 人员分配） | `MatchState.logicalCourts` | 以运动员面对球网为准 |
| `physicalEnds`（物理场地端） | `MatchState.physicalEnds` | `END_1` / `END_2`，由换边命令改变 |
| `flipped`（本机视角） | `sessionStorage`，**不进比赛状态** | 只改投影与设备偏好 |

投影函数 `buildCourtViewModel`（`src/ui/court-view-model.ts:153`）把权威状态映射到屏幕，
不推导任何计分或轮转规则。本轮新增 `displayedLeftSide` / `displayedRightSide`，
供比分栏与 `+1` 直接取当前画面这一侧的**稳定 sideId**。

### 默认视角的固定映射

假定画面左方运动员向右面对球网、右方运动员向左面对球网：

| 在画面哪边 | 本方逻辑左区 | 本方逻辑右区 |
|---|---|---|
| 画面左半场 | 屏幕上格 | 屏幕下格 |
| 画面右半场 | 屏幕下格 | 屏幕上格 |

因此双方的「右发球区」是画面对角的两个格，不在同一水平行。
实现见 `logicalCourtForCell`（`court-view-model.ts:53`），本轮核验与需求包坐标图一致，未改动。

换边后由 `physicalEndAssignment` 重新决定每个半场归属哪一方，
上下格也随之按该方 L/R 重新投影，不是把两队从左平移到右。

## 3. 场线绘制（按 Diagram A）

`src/ui/court-geometry.ts` 以厘米为单位定义几何，`viewBox` 为 `0 0 1340 610`，即 13.40 m × 6.10 m，长宽比约 2.2:1。

- 前发球线距球网 1.98 m；
- 双打后发球线距端线 0.76 m；
- 单打边线距双打边线 0.46 m；
- **中线只从端线画到前发球线**，不穿过前场，也不跨越球网；
- 球网是器材，用虚线单独表示，不与正式场线同色同粗。

逻辑发球区只用极淡底色（`--court-zone`）分区，与正式白线有明显视觉区别。
四个方框只表示「下一次发接发的逻辑区域」，**不追踪回合中的实际跑位**；
非发接球员所在格只是次序标识。

## 4. 发接发标记

- 发球者姓名区显示**唯一**一枚羽毛球 SVG ＋「发球」；
- 接发者用「接发」标签加描边，**不再放第二枚羽毛球**；
- 图标、姓名与文字提示全部来自同一份服务器确认状态（`roleForCell`）；
- 未确认首发时只显示「拟首发／拟首接」且**不显示羽毛球**，不伪造当前发球者；
- 暂停时文案改为「比赛暂停中，恢复后再确认下一球发球」。

## 5. 长姓名处理

本轮修复 REF-001：移除了球员卡、队名条与比分栏原有的 `white-space: nowrap` + `ellipsis`
和手机端的 `-webkit-line-clamp: 2`。现在长姓名与长代表队名一律换行（`overflow-wrap: anywhere`），
不会为适配截掉第二名双打运动员。另提供「查看全名与代表队」可展开列表，
不把 tooltip 作为唯一获取方式。

## 6. 视觉与适配

裁判端专属变量挂在 `.scoring-shell` 作用域上，不改 `:root`，不污染管理端与公开端：

```css
--court-turf / --court-turf-deep / --court-line / --court-zone
--serve-warm / --serve-warm-ink / --ops-blue
```

采用深绿球场、蓝色操作区、白/浅灰信息面板、少量暖色发球标记；无霓虹发光与厚重渐变。

- 换位/换边按钮 ≥ 48px，`+1` 更大（≥ 58px），比分用 `tabular-nums`；按钮有文字，不只靠颜色区分。
- 桌面保持约 2.2:1；**手机放宽比率**（`aspect-ratio: auto` + `min-height: clamp(230px, 62vw, 300px)`），
  以保证姓名可读——这是提示词明确允许的移动端调节。
- 已在 390×844、820×1180、1180×820、1440×1000 与 320×720 实际检查，无根级横向溢出。

## 7. 次要操作折叠

`<details class="secondary-drawer">` 收纳：暂停、LET、详细比分/发球权更正、发接发顺序更正、
异常结果、裁判长接管、翻转本机视角、最近操作记录，以及提交/复核锁定/退回补正/受控重开。

**刻意留在首屏**（时机敏感，误藏会影响执裁）：

- 抛币按钮（只在 `AWAITING_COIN_TOSS` 出现）；
- 首发/首接设置面板；
- `确认间歇完成` / `记录漏换后补做` 等待办；
- `恢复比赛`（暂停后的唯一出路）。

当比赛进入 `MATCH_COMPLETE_PENDING_SUBMISSION`、`SPECIAL_OUTCOME_PENDING_SUBMISSION`、
`SUBMITTED` 或 `CONFIRMED` 时，抽屉**默认展开**，避免把提交或复核这关键一步藏起来。

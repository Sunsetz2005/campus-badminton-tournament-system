# 裁判端交互规范

主裁判端是 V1 的高风险核心。界面必须反映服务器权威状态，不能做“按钮看似成功、后台未保存”的演示壳。

## 比赛生命周期

```text
SCHEDULED
  → READY_FOR_COIN_TOSS
  → READY_FOR_OPENING_SETUP
  → IN_PROGRESS
  ↔ PAUSED / INTERVAL
  → PENDING_RESULT_CONFIRMATION
  → CONFIRMED
```

弃权、退赛、取消或中止使用受权限控制的特殊分支。`CONFIRMED` 后普通主裁判不能回到 `IN_PROGRESS`。接管状态和联网状态是正交维度，不应被硬塞成比赛生命周期。

## 页面区域

| 区域 | 必须展示/操作 |
|---|---|
| 顶部状态 | 比赛编号、项目、当前局、联网状态、服务器确认状态、控制设备、只读原因 |
| 对阵与比分 | A/B 固定身份、双方姓名/组合、大号当前比分、已完成局比分 |
| 得分操作 | 双方独立大按钮 `+1`、清晰的更正入口、撤销上一操作 |
| 发接发信息 | 发球方、发球员、接发球员、逻辑发球区、“谁发给谁” |
| 场地图 | 单双打球员逻辑位置、双方物理场地端、屏幕方向 |
| 辅助操作 | 左右状态更正、物理换边、视角翻转、间歇、暂停、LET、特殊结果 |
| 历史与提交 | 命令状态、操作历史、前后对比、结束提交、结果复核/锁定 |

## 开赛前

1. 裁判只看到本人获授权比赛；取得写租约后才能进入可操作状态。
2. 抛硬币支持记录现场结果或软件随机辅助。保存胜方及其“发/接发或场地”选择，另一方选择剩余事项。
3. 已保存的抽签不能通过刷新重抽。重新抽签需要权限、原因和追加历史。
4. 每局开局确认首发方、发球员、接发球员、双方物理端；双打显示四名具体球员。

## 设备提交状态

```text
SYNCED
  → SUBMITTING(commandId)
  → CONFIRMED
  ↘ UNKNOWN → RECONCILING → CONFIRMED / CONFLICT

OFFLINE_READ_ONLY
STALE_VERSION_READ_ONLY
NOT_CONTROLLER_READ_ONLY
```

- 只有 `CONFIRMED` 才把操作显示为服务器成功。
- `UNKNOWN` 保留原命令 ID并阻止重复点击造成新命令；刷新后仍要找回。
- `CONFLICT`、失去租约或断网时先切只读，再拉取权威状态。
- V1 不允许离线继续记分，恢复连接后先同步再开放按钮。

## 得分、撤销和更正

点击 `+1` 后按钮进入提交中，成功响应带回新版本和完整必要快照。更正入口先展示最近一分及撤销后的比分、发接发、位置和提示变化；非最近一分或规则位置更正进入有原因、有权限的专门流程。

手动左右调整、物理换边、屏幕翻转使用不同图标、标题和确认文案。屏幕翻转无需产生比赛业务事件；物理换边必须等待服务器确认。

## 结果确认

提交前展示每局比分、特殊结果、双方身份和未解决的待确认命令。主裁判提交后进入待复核；确认/锁定由配置的授权角色完成。结果锁定后若需更正，跳转影响预览，不在比分页静默改值。

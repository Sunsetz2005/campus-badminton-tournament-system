# 页面与流程

阶段 1 建立了首页、登录、赛事管理、我的执裁、公开查询和设置的中文响应式骨架。阶段 3 已实现受保护的权威裁判工作台；报名、编排、排名、成绩册以及完整公开赛程/成绩仍未实现。每个写操作仍必须对应服务端权限和明确反馈。

当前 `/public` 固定读取 `phase-1-demo`，只证明服务端白名单骨架，不是完整公开查询。UI-01-A 已完成参考核验和设计规范；UI-01-B 已实现非生产显式开关控制的每日赛程/比赛详情隔离模拟预览，其中每日赛程的本轮视觉修正待用户确认。UI-01-C 真实公开接口尚未实现。

## 页面结构

| 区域 | 页面/能力 | 主要角色 | 关键状态 |
|---|---|---|---|
| 登录与工作台 | 登录、本人任务、赛事切换 | 内部角色 | 未登录、无权限、待处理 |
| 赛事设置 | 基本信息、项目、规则、场地、账号 | 管理员 | 草稿、开放报名、编排中、进行中、已归档 |
| 名册录入 | 手工录入、Excel/CSV 导入预览、双打成员、重复/错误处理 | 组织人员 | 草稿、预览、已导入、部分失败 |
| 分组编排 | 名单、种子、回避、循环/淘汰签表 | 组织人员 | 草稿、已发布、存在冲突 |
| 赛程调度 | 时间、场地、裁判、冲突检查 | 组织人员 | 未排、已排、冲突、变更待通知 |
| 主裁判工作台 | 接管、抛硬币、开局、记分、更正、提交 | 主裁判/裁判长 | 见[裁判端交互规范](裁判端交互规范.md) |
| 成绩复核 | 结果确认、更正申请、影响预览 | 裁判长/管理员 | 待复核、已锁定、更正中 |
| 名次晋级 | 小组排名解释、晋级、后续签位 | 组织人员 | 待结果、可计算、受更正影响 |
| 报表中心 | 基于锁定快照生成版本化成绩册、打印和替代记录 | 管理员/组织人员 | 草稿、已复核、已发布、已被替代 |
| 公开查询 | 服务端白名单返回赛程、成绩、名次和版本 | 公众 | 只读、脱敏、临时、正式、争议 |

## 三端界面边界

| 界面 | 目标 | 数据/权限边界 |
|---|---|---|
| 公开端 | 快速查询何时、何地、谁对谁、比分与正式结果 | 完全只读，只接公开发布与隐私投影；不得复用裁判状态接口 |
| 管理端 | 录入、编排、冲突处理、复核与发布 | 保留后台效率，所有写权限由服务端执行 |
| 裁判端 | 稳定 A/B、发接发/位置、比分、撤销、换边与控制权 | 继续使用权威事务、租约和命令接口，不套用公众列表布局 |

公开端详细规范见[亚运会网站参考与本项目界面规范](亚运会网站参考与本项目界面规范.md)和[公开赛程与成绩中心：页面与状态清单](公开赛程与成绩中心-页面与状态清单.md)。

## 主业务流程

| 步骤 | 输入 | 成功输出 | 阻断条件 |
|---|---|---|---|
| 创建赛事 | 名称、时间、项目和规则 | 赛事草稿 | 缺少必要规则确认 |
| 导入名册 | 线下审核结果、手工输入或表格 | 新增/重复/错误预览 | 字段缺失、重名未区分、双打成员错误 |
| 确认名册 | 导入预览、幂等键 | 参赛名单版本 | 重复批次、同项目重复、资格待复核 |
| 分组编排 | 已通过名单、种子、约束 | 可追踪签表 | 约束无解或人工调整未说明 |
| 安排赛程 | 签表、场地、时间和裁判 | 已排比赛 | 场地/人员/休息冲突 |
| 临场执裁 | 指派、租约、抛硬币和开局状态 | 权威逐分历史和结果 | 无权限、无租约、断网、版本冲突 |
| 复核排名 | 已确认结果、排名规则 | 可解释名次和晋级 | 结果未锁定、规则未确认 |
| 发布报表 | 已复核数据、公开范围 | 下载文件和查询页 | 隐私字段未确认、生成失败 |

## 阶段 4-B 已实现的团体赛流程

| 步骤 | 页面 | 角色 | 结果与阻断 |
|---|---|---|---|
| 建团体项目 | `/management/new` 或赛事概览「新增项目」 | 平台管理员 / 赛事管理员 | 选「团体赛」，可调整小场顺序（默认男单、女单、男双、女双、混双）与名单人数 |
| 建学院、开通负责人 | `/management/[slug]/teams` | 管理员（开通/重置/移除账号）、编排员（建队、代录） | 初始口令只在开通后显示一次；刷新即不可再看，只能重置 |
| 首次登录改口令 | `/account/password` | 负责人 | 未改口令前访问「我的队伍」一律跳转，提交接口 403 |
| 提交本院名单 | `/team` → `/team/[slug]` | 负责人 | 报名窗口内提交；学号与性别必填；人数、男女下限、跨队学号冲突逐条报错；待审核可修改或撤回；通过后只读 |
| 审核名单 | `/management/[slug]/registrations` | 管理员/编排员 | 复用 4-A 身份判定，通过后生成以学院命名的团体报名单位 |
| 抽签草稿 | `/management/[slug]/draw` → `/draw/[code]` | 管理员/编排员 | 按队数建议赛制；可设种子与依据；显示分组、签表、对阵、冲突原因与复现依据；可反复重抽、手动交换或移组（须原因） |
| 正式发布 | 同上 | 管理员/编排员 | 须报名截止、无待审核、名单未变；确认后生成对抗与五个小场占位并冻结名单 |
| 撤销发布 | 同上 | 裁判长 | 须原因；任一比赛开始即拒绝 |

## 阶段 4-D 已实现的团体对抗流程

| 步骤 | 页面 | 角色 | 结果与阻断 |
|---|---|---|---|
| 报项 | `/team/[slug]` 名单编辑（管理员代录同一编辑器） | 负责人 / 管理员 | 选性别后只出现可报的小场复选框；每人至少 1 项；某小场报项人数不够时逐条报错 |
| 查看对抗 | `/team/[slug]`「团体对抗与出场名单」 | 负责人 | 只列本队参加的对抗；显示对手（或「某组第几名」待定）、本队名单状态、大比分 |
| 盲交出场名单 | `/team/[slug]/ties/[fixtureId]` | 负责人 | 每个位置只列报了该项且性别相符的队员；兼项不设上限，只提示；交齐前可修改（带版本）；对方列只显示「未提交/已提交，未公开」 |
| 代交与进度 | `/management/[slug]/ties` → `/ties/[code]` → `/ties/[code]/[fixtureCode]` | 管理员/编排员 | 交齐前后台也只见提交状态；代交整份覆盖该方；交齐即双方同时公开并锁定 |
| 调整上场队员 | 单场对抗页 | 裁判长 | 只能改未开始、无控制会话的小场；原因必填，前后名单进审计 |
| 执裁 | 单场对抗页小场编号 → `/officiating/[matchCode]` | 裁判长（指派的主裁判经「我的执裁」） | 标题显示「第 n 场某小场」，两侧为学院，上场队员取自出场名单；名单未交齐 `match_not_ready`，「未进行」小场 `rubber_not_played` |
| 对抗胜负 | 单场对抗页、`/ties/[code]` | 自动 | 只计裁判长锁定的小场；小组打满、淘汰决出即止；淘汰胜负者自动进入下一轮 |
| 积分榜与名次 | `/management/[slug]/ties/[code]` | 裁判长确认 | 组内全部结束后可确认；须抽签时只能调整相同的几队并写明抽签情况；确认后回填淘汰签位；本组结果重开会撤回确认 |

后台团体对抗页沿用赛事后台的访问门槛（`ADMIN`/`ORGANIZER`），裁判长专属操作只在同时持有 `CHIEF_REFEREE` 时出现；只有裁判长角色、没有管理角色的账号暂时无法在界面上确认名次（接口本身只认裁判长）。4-C 为裁判长补了现场看板（临时换裁判），名次确认界面仍未补齐。

## 阶段 4-C 已实现的赛程与裁判排班流程

| 步骤 | 页面 | 角色 | 结果与阻断 |
|---|---|---|---|
| 设置 | `/management/[slug]/schedule?view=settings` | 管理员/编排员 | 预计时长、换场时间、淘汰赛每场对抗占用场地数、名单截止提前量；按数量追加场地、改名、关闭/重新开放；比赛日与开放时段 |
| 自动建议 | 「草稿编排」 | 管理员/编排员 | 选项目/阶段/最早开始；小组一组一块场地（场地多于小组时各组分多块）、对抗 5 个小场同一场地连打，淘汰赛占设置的场地数并行、在全部前序比赛之后；个人项目择早；可同时建议主裁判；排不下的列出原因并撤下时间 |
| 手工调整 | 每行「调整」（手机表单，不需拖拽）；「整场对抗重排」 | 管理员/编排员 | 改场地/开始/预计时长/主裁判/预计标记，保存即返回这一场的复检；已开始的比赛不能调整 |
| 检查 | 「草稿检查与发布」 | 自动 | 硬冲突（同场地、同一人、同队两场、同裁判、非裁判员、场地关闭、依赖未排/过早、已开始被改）阻止发布；警告（暂定晋级、超出时段、未指派裁判）须勾选确认；待晋级比赛标「暂定对阵」 |
| 发布 | 同上 | 管理员/编排员 | 写入计划时间与场地、同步主裁判到「我的执裁」、已排定比赛进入公开赛程、保存版本与差异；已发布赛程之后出现硬冲突（关场地、晋级确定后重叠）时页顶红色提示 |
| 我的执裁 | `/officiating` | 主裁判 | 按真实指派列出比赛的时间（预计时间带「约」）、场地、小场；前面比赛超时造成的延误提示 |
| 现场看板 | `/officiating/board/[slug]`；后台「已发布与现场」 | 裁判长；管理员 | 待开赛/进行中/已结束/延误（含原因）；裁判长临时更换裁判须写原因，并提示新裁判的时间重叠 |
| 名单截止 | `/team/[slug]`、`/team/[slug]/ties/[fixtureId]`、后台单场对抗 | 负责人 / 管理员 | 显示计划开始、场地与截止时间；截止后负责人只读并提示联系管理员，管理员代交标「逾期代交」；同时进行的小场不能同一人，按兼项上限提示 |

## 公开端补充流程

1. UI-01-B 只在非生产显式开关下提供每日赛程和比赛详情的隔离预览，始终标注“模拟数据／界面预览”。
2. UI-01-C 只有在逐场发布快照、隐私投影、赛事时区日期、可信时间和公开投影版本契约具备后才接真实服务。
3. 对阵、排名、最终名次和成绩册继续等待权威业务服务；UI 不自行计算或伪造正式结果。

## 通用反馈要求

- 保存中、服务器已确认、待确认、冲突、只读和离线必须有不同视觉/文案，不能用同一个绿色提示代替。
- 破坏性或高影响操作显示对象、前后差异和原因输入。
- 移动端核心操作不依赖悬停；得分按钮足够大且双方不易误触。
- 页面刷新后从服务器恢复权威状态及待确认命令，不从旧 localStorage 猜测成功。
- 空状态、加载失败、无权限和数据冲突都提供下一步，而不是空白页。

## 模板边界

资料包的 `public-results-demo.html`、`results-booklet.html/pdf` 和 `demo-data.json` 只作为版式与字段参考。当前项目不复制其模拟成绩为真实数据，不把本地筛选当成公开查询功能，也不把固定 7 页排版当成动态报表已完成。集成要求见[成绩册与公开查询模板说明](../08-成果材料/成绩册与公开查询模板说明.md)。

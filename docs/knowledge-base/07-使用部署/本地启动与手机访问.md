# 本地启动与手机访问

> [!warning] 使用边界
> 当前是本机/局域网开发演示，不是可直接暴露公网的生产服务。完整计分、编排、成绩和裁判工作台尚未实现。

## 当前 Mac 启动

仓库已通过 pnpm 项目 runtime 固定 Node 24.21.0，不需要修改系统 Node 26。

```bash
pnpm install --frozen-lockfile
pnpm exec node --version
pnpm run db:migrate
pnpm run db:seed
pnpm dev
```

预期 `pnpm exec node --version` 为 `v24.21.0`。浏览器访问 `http://127.0.0.1:3000`，健康检查为 `http://127.0.0.1:3000/api/health`。停止时在运行终端按 `Ctrl+C`。

首次检出需把 `.env.example` 复制为不提交的 `.env`，填写本机开发库和至少 32 字符的随机认证密钥。示例账号变量放在单独、被忽略的 `.env.seed`；知识库不保存密码。`pnpm run db:seed` 使用 Better Auth 提供的密码哈希创建本地身份，会拒绝未知数据库和生产环境；网页公众注册始终关闭。

## 浏览器验收路径

1. 打开首页，确认明确显示“阶段 1 工程骨架”，而不是完整系统。
2. 打开“公开查询”，刷新页面后模拟对阵仍存在；公开 API 不应出现邮箱、内部 ID、token 或审计字段。
3. 使用 `.env.seed` 中管理员身份登录，进入“赛事管理”可看到授权赛事；调用比赛控制接口应得到 403，管理员不能替代裁判。
4. 退出后使用临场裁判身份登录，“我的执裁”只显示 `MS-DEMO-001`；未指派的双打比赛不能取得控制权。
5. 打开“设置”核对当前账号和赛事角色；关闭服务再启动，公开数据和指派仍应存在。

## 测试与数据库隔离

首次运行前复制 `.env.test.example` 为 `.env.test`，填写独立的 `_test` 数据库连接、测试密钥和两个模拟身份。模板中 `BETTER_AUTH_URL` 固定为 Playwright 使用的 `http://127.0.0.1:3100`。

```bash
pnpm run lint
pnpm run typecheck
pnpm test
pnpm run test:e2e
pnpm run build
```

`pnpm test` 和 `test:e2e` 只接受数据库名以 `_test` 结尾。当前本机开发库为 `badminton_tournament_dev`，测试库为 `badminton_tournament_test`。自动化脚本不会重置或删除其他数据库；缺少 `.env.test` 时会明确提示先按模板创建。

## 局域网访问边界

开发服务监听 `0.0.0.0`，同一局域网设备理论上可通过 `http://Mac局域网IP:3000` 访问，但本轮没有使用真实手机/平板或检查防火墙，因此局域网实机状态是“未运行”。不得把 localhost 或 Playwright Chromium 结果写成手机验收通过。

局域网 HTTP 也不等于安全生产部署；HTTPS、反向代理、备份恢复和生产密钥轮换均未执行。

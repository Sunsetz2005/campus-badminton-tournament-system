# 本地启动与手机访问

> [!warning] 使用边界
> 这里说的是本机/局域网**开发**运行，不是可直接暴露公网的生产服务；开发服务器端口不得直接暴露到公网。
> 公网部署另走生产构建、HTTPS、认证与备份流程，见[备份恢复与部署](备份恢复与部署.md)。
> 截至 2026-09-29 仍**没有**做过真机手机/平板执裁，也没有配置 HTTPS。

## 当前 Mac 启动

仓库已通过 pnpm 项目 runtime 固定 Node 24.21.0，不需要修改系统 Node 26。

```bash
pnpm install --frozen-lockfile
pnpm exec node --version
pnpm run db:migrate
pnpm run db:seed
pnpm dev
```

预期 `pnpm exec node --version` 为 `v24.21.0`。浏览器访问 `http://127.0.0.1:3000`，健康检查为 `http://127.0.0.1:3000/api/health`。停止时在运行终端按 `Ctrl+C`。

首次检出需把 `.env.example` 复制为不提交的 `.env`，填写本机开发库和至少 32 字符的随机认证密钥。示例账号变量放在单独、被忽略的 `.env.seed`；知识库不保存密码。`pnpm run db:seed` 使用 Better Auth 提供的密码哈希创建本地身份，会拒绝未知数据库和生产环境；网页公众注册始终关闭。

## 浏览器验收路径

1. 打开首页，确认页面明确标注当前开发阶段，而不是完整系统。
2. 打开“公开查询”，刷新页面后模拟对阵仍存在；公开 API 不应出现邮箱、内部 ID、token 或审计字段。
3. 使用 `.env.seed` 中管理员身份登录，进入“赛事管理”可看到授权赛事；调用比赛控制接口应得到 403，管理员不能替代裁判。
4. 退出后使用临场裁判身份登录，“我的执裁”只显示已指派比赛；未指派的比赛不能取得控制权。
5. 进入已指派比赛的裁判工作台，取得本机控制权后可抛币、确认首发首接并加分；所有操作都要等服务器确认后才更新界面。
6. 打开“设置”核对当前账号和赛事角色；关闭服务再启动，公开数据和指派仍应存在。

## 测试与数据库隔离

首次运行前复制 `.env.test.example` 为 `.env.test`，填写独立的 `_test` 数据库连接、测试密钥和两个模拟身份。模板中 `BETTER_AUTH_URL` 固定为 Playwright 使用的 `http://127.0.0.1:3100`。

```bash
pnpm run lint
pnpm run typecheck
pnpm test
pnpm run test:e2e
pnpm run build
```

`pnpm test` 和 `test:e2e` 只接受数据库名以 `_test` 结尾。当前本机开发库为 `badminton_tournament_dev`，测试库为 `badminton_tournament_test`。自动化脚本不会重置或删除其他数据库；缺少 `.env.test` 时会明确提示先按模板创建。

## 同一 Wi-Fi 下用手机访问（阶段 8）

`pnpm dev` 等价于 `next dev --hostname 0.0.0.0`，监听本机全部网卡的 3000 端口。步骤：

1. Mac 与手机连同一个 Wi-Fi（不要用访客网络——很多路由器的访客网络开启了「客户端隔离」，设备之间互相访问不到）。
2. 在 Mac 上启动：`pnpm dev`。
3. 确认实际监听地址（应看到 `*:3000` 或 `0.0.0.0:3000`，而不是 `127.0.0.1:3000`）：

   ```bash
   lsof -nP -iTCP:3000 -sTCP:LISTEN
   ```

4. 查 Mac 的局域网 IP（Wi-Fi 通常是 en0）：

   ```bash
   ipconfig getifaddr en0
   ```

5. 先在 **Mac 本机**用局域网 IP 自检：`curl http://<局域网IP>:3000/api/health` 应返回 200。这一步只证明服务确实监听在局域网网卡上，不等于手机能访问。
6. 手机浏览器打开 `http://<局域网IP>:3000`。**不能**在手机上访问 `localhost`——那指的是手机自己。
7. 登录：开发环境会自动把「本机当前局域网 IPv4 + 同端口」加入登录受信来源（取自本机网卡，不取自请求头）。**换了 Wi-Fi 或 IP 变化后要重启 `pnpm dev`**。生产环境不会自动信任，需要在 `APP_TRUSTED_ORIGINS` 里显式写出完整来源。

2026-09-29 本机实测（开发库，未用真实手机）：`lsof` 显示 `node … TCP *:3000 (LISTEN)`；经局域网 IP 的健康检查 200；以局域网 IP 为来源的登录请求通过来源校验（用故意错误的口令得到 401「账号或密码错误」，而不是 403 `INVALID_ORIGIN`），跨站来源仍被 403 拒绝。修复前，`.env` 的 `BETTER_AUTH_URL` 为 127.0.0.1 时，局域网 IP 甚至 `localhost` 来源的登录都会被 403 拒绝——也就是手机此前**无法登录**。

### 访问不到时的诊断（不要随意关闭系统安全设置）

| 现象 | 先查 |
|---|---|
| Mac 上 `curl 局域网IP:3000` 就失败 | `lsof` 是否监听 `*:3000`；是否误用了只绑 127.0.0.1 的启动方式 |
| Mac 自检通过、手机打不开 | 两台设备是否同一网段（手机 Wi-Fi 详情里的 IP 前三段应与 Mac 相同）；路由器是否开启客户端/AP 隔离；手机是否开着 VPN 或「私人中继」 |
| 偶尔能开、隔一会儿打不开 | Mac 是否休眠（执裁期间接电源并在「电池」设置里防止自动睡眠）；是否切换了 Wi-Fi |
| macOS 弹出「是否允许 node 接受传入连接」 | 选「允许」。若曾选过拒绝，到「系统设置 → 网络 → 防火墙 → 选项」只为 node 改为允许，**不要**整体关闭防火墙 |
| 页面能开但登录报「来源无效」 | IP 变了没重启 `pnpm dev`；或是生产模式没有配置 `APP_TRUSTED_ORIGINS` |

### 添加到主屏幕与屏幕常亮

- 已提供应用清单与图标：iPhone Safari「分享 → 添加到主屏幕」、Android Chrome「⋮ → 添加到主屏幕」可以得到「赛事台」图标，以独立窗口打开。
- **没有**注册 Service Worker：比分、执裁命令和登录状态都不进缓存，断网时页面不会假装可用，也不会在执裁中被后台更新无提示替换。离线记分不是本版本能力。
- 裁判持有控制权时，工作台会申请屏幕常亮，状态栏显示「常亮 已开启/未开启/不可用/被系统拒绝」。浏览器只在 HTTPS 或 localhost 下提供这个能力，**手机经局域网明文 HTTP 访问时一定不可用**，页面会提示：执裁期间在手机设置里把「自动锁定」暂时改为「永不」，赛后改回。

## 局域网访问边界

局域网 HTTP 能打开页面、能登录，不等于可以正式执裁：真机、真人裁判、长时间运行、系统浏览器旋转与软键盘都还是**未测试**，见[阶段 8 验收](../05-测试验收/阶段8-移动端与可靠性验收.md)的手机手动验收清单。不得把 localhost 或 Playwright Chromium 结果写成手机验收通过。

局域网 HTTP 也不等于安全生产部署；HTTPS、反向代理、备份恢复和生产密钥轮换均未执行。

### 安全上下文与命令 ID（R3-005）

电脑上的 `http://localhost` 是浏览器认可的**安全上下文**，手机通过 `http://Mac局域网IP:3000` 访问的明文 HTTP **不是**。
`crypto.randomUUID()` 只在安全上下文可用，因此两者的浏览器能力并不相同。

裁判工作台在进入可写界面**之前**检测所需能力，不会等到按加分时才抛原始异常：

| 访问方式 | 命令 ID 来源 | 界面行为 |
|---|---|---|
| HTTPS 或 `localhost` | `crypto.randomUUID()` | 正常可写 |
| 局域网明文 HTTP，浏览器提供 `crypto.getRandomValues` | 按 RFC 4122 第 4 版从密码学安全随机字节构造 UUID | 可写，但页面常驻提示「正式执裁请改用可信 HTTPS」 |
| 两种安全随机源都没有 | 无 | 保持只读，并显示可理解的原因 |

兼容路径**没有**使用 `Math.random`，也**没有**关闭浏览器安全策略、认证或 CSRF。
但只解决命令 ID **不等于** 手机执裁已经可用：正式执裁仍需可信 HTTPS 和真机试用，这些**都还没有做**。（局域网登录来源已于阶段 8 修复，见上文。）

# 备份恢复与部署

## 阶段 0 知识库同步

权威源固定为仓库 `docs/knowledge-base/`，目标固定为：

```text
/Users/a10954/Documents/Documents - Sunsetz的MacBook Pro/Obsidian Vault/羽毛球赛事管理系统
```

同步只允许从仓库到 Vault，不从 Vault 反向覆盖仓库。

```bash
node scripts/sync-knowledge-base.mjs --dry-run
node scripts/sync-knowledge-base.mjs --apply
node scripts/sync-knowledge-base.mjs --dry-run
```

默认无参数等同 dry-run。脚本不接受自定义目标参数，阶段 0 只处理 Markdown。

## 安全行为

- 在任何写入前核对源、Vault、唯一目标和所有现有路径组件，拒绝符号链接和越界路径。
- `.badminton-kb-sync.json` 记录工具拥有的相对路径、大小和 SHA-256。
- 新源文件若遇到未知同名目标，或已管理目标与上次哈希不同，整次写入在预检阶段停止。
- 目标中的未知额外 Markdown 保持不动；源文件删除只报告 `STALE`，不会删除目标。
- 更新已管理文件前备份到仓库 `.local/kb-sync-backups/<timestamp>/`，该目录不提交 Git。
- 文件通过同目录临时文件原子替换；成功后重新读取目标并核对哈希。

## 冲突处理

出现 `CONFLICT` 时不要使用复制命令强制覆盖。先比较仓库源、目标文件、清单和最近备份，判断是用户误改同步副本、清单损坏还是未知文件占位。将需要保留的人工内容明确迁回仓库源文件，审核后再处理冲突；脚本不会自动合并。

只有人工内容已经逐字合并进仓库、仓库与目标哈希完全相同且不存在其他待同步变更时，才可运行：

```bash
node scripts/sync-knowledge-base.mjs --adopt-target
```

该命令只备份并更新清单基线，不改目标正文。内容不一致、目标缺失、存在其他新建/更新/陈旧文件或其他冲突时都会拒绝。

## 恢复同步文件

如果更新后发现文档内容错误，先停止再次同步，从 `.local/kb-sync-backups/` 找到最近副本，与 Git 中的权威源对比。修复仓库源并通过 dry-run 后重新发布。不要把备份目录整体复制进 Vault，也不要删除目标中的未知文件。

## 赛事海报：部署前必须挂数据卷

阶段 4-0 引入管理员上传的赛事海报，服务端写入仓库内的 `public/posters/`。

**这是运行时数据，不是镜像内容。** 根级 `.dockerignore` 已排除 `public/posters/*`（只保留 `.gitkeep`），
`.gitignore` 同样排除。因此如果不为该目录挂卷，**每次重建或回滚镜像，已上传的海报都会全部丢失**，
而数据库里的 `tournaments.posterPath` 仍指向这些文件，页面会出现坏图。

部署到演示服务器时，需要在 Compose 的 app 服务上增加一个具名卷：

```yaml
services:
  app:
    volumes:
      - campus-badminton-posters:/app/public/posters

volumes:
  campus-badminton-posters:
```

配套要求：

- 卷路径必须与容器内的 `process.cwd()/public/posters` 一致；应用启动时会按需 `mkdir -p`。
- 备份范围要同时覆盖数据库快照和这个卷；只备份数据库会得到一份指向不存在文件的记录。
- 卷内只应出现服务端生成的 `<uuid>.{webp,jpg,png}`。文件名由 `randomUUID()` 生成，绝不采用上传名；
  数据库上的 `tournaments_poster_path_check` 是第二道兜底。
- 缺图时页面回退到按 slug 确定性生成的纯 CSS 渐变占位卡，不会请求任何外链资源，因此丢卷不会导致页面报错，只会退化为占位卡。

截至本次记录，公网演示站**尚未**配置该卷，也尚未上传任何海报；上线海报功能前必须先补上。

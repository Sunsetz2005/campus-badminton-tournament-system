## 修复

| 编号 | 问题 | 修复 |
|---|---|---|
| AR-01 | 现场看板与 `GET /api/public/tournaments/[slug]` 共用的阶段 1 白名单没有逐场发布边界，也不看姓名公开策略：匿名可读到未公开的比赛与报名单位真实名称 | `publicTournamentSelect` 加 `publishedMatchWhere`；`loadPublicTournament` 读取 `namePolicy`，`CODES_ONLY` 时把名称换成编号，策略本身不下发 |
| AR-02 | 登录后跳转 `safeNextPath` 只拦 `//` 与 `/\`；浏览器解析地址时会丢弃制表符与换行，`/%09/evil.example` 实际等于 `//evil.example` | 含控制字符或反斜杠一律拒绝，并按浏览器规则实际解析一次，来源变化即退回首页。（浏览器里的完整跳转链路没有实测，按解析结果判定。） |
| AR-03 | `pnpm run lint` 在本机报 99,625 个问题，全部来自未跟踪的 `.claude/worktrees/**`（含其 `.next` 产物）与 `.local/**` | `eslint.config.mjs` 忽略这两个目录与 `test-results/**` |
| AR-04 | 记分命令的 `payload` 是任意对象：`physicalEnds: { A: "foo", B: "bar" }`、抛币的非法端位与发球选择会被引擎接受并写入权威状态；多余字段、不限长的原因原样入库并参与此后每次重放；请求体没有全站统一的上限 | `scoring-command-schema.ts` 增加逐命令 zod 形状（枚举、长度上限，未列出的字段丢弃）与 16 KiB 请求体上限；只作用于新命令，历史事件重放不受影响 |
| AR-05 | 读取权威状态对比赛行加 `FOR UPDATE`，裁判台与裁判长的轮询彼此排队 | 改为 `FOR SHARE`（读与读不互斥，仍等待正在提交的写入）；比赛尚无权威快照时回退到 `FOR UPDATE` 重读一次，避免并发创建 |
| AR-06 | 引擎 `createEvent` 每条命令把全部历史事件深拷贝一遍，重放成本按事件数平方增长；重放查询把不参与重放的响应与哈希列也读出来 | 历史事件对象在聚合间共享（写入后不再修改）；重放只取需要的列 |
| AR-07 | `stableStringify` 用 `localeCompare()` 排序键，结果取决于进程语言环境；换一个语言环境不同的容器，状态哈希可能全部对不上 | 固定用 `Intl.Collator("en")`（与此前在英语环境下写入的顺序一致）；新增用例钉住键顺序与一份初始状态的哈希 |
| AR-08 | 重放与创建初始状态时引擎抛出的规则异常不是 `AppError`，接口上表现为笼统的 500 | 转成 409 `event_history_unreplayable` / `match_not_ready` |
| AR-09 | `registration.test.ts` 用全库用户数断言「匿名报名不创建账号」，并行运行的其他测试文件增删用户时偶发失败（本次第一次全量运行实测：期望 24、实得 18） | 只统计与本赛事或报名人有关的账号，并断言报名记录没有提交人账号 |

AR-05 的第一版用「可重复读快照、完全不加锁」，端到端 3 项失败（`referee-boundary-ui` 两项、`mobile-reliability` 一项）：用例与工作台都依赖「刚写完立刻读，读到的是已提交的最新版本」，无锁快照读会读到上一版，随后的命令被 409 `conflict` 拒绝。改为共享锁后恢复这一保证，三项通过。

AR-01 顺带把 `tests/integration/public-fields.test.ts` 的唯一用例并入 `public-results-projection.test.ts`：它断言 `MS-DONE-001` 可见，而后者会临时取消这场比赛的发布，两个文件并行运行会互相干扰。

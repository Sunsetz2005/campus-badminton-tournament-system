# 当前进度与下一步

## 当前事实

- 阶段 0 的需求、架构、规则、交互、测试和安全同步文档已完成。
- 阶段 1 的 Next.js/React/TypeScript 工程、PostgreSQL 迁移、Better Auth 登录、服务端角色/指派校验、公开白名单和最小控制会话基础已完成。
- Claude 独立复验判定阶段 1 必需验收通过；后续 S1-010—S1-014 也已全部复验通过。
- 阶段 2 已实现纯 TypeScript 规则引擎：三个演示 profile、抛币、单双打逐分、双打 R/L、发接发、间歇、物理换边、撤销、更正、暂停、特殊结果、提交/确认/重开和确定性重放。
- 规则引擎不读取数据库、网络、当前时间或随机数；命令时间和抛币事实从外部输入。屏幕方向不进入比赛状态。
- Claude 阶段 2 第二轮独立复验判定 S2-002、S2-003、S2-006 通过，S2-001 的替换值校验通过但命令入口阶段门禁缺失，遗留部分另立 S2-007。
- S2-007 第 3 轮独立复验通过：四类更正的结果锁、比分更正 phase 白名单和 `REOPEN_RESULT` 受控重开通路同时成立。
- S2-008 已在 `CORRECT_PHYSICAL_ENDS` 中新增 `obligationRelationship`：`FULFILL` 表示现场已换边并消费待办，`KEEP_PENDING` 只更正原端位记录并保留换边待办；已通过本地回归，待独立复验。
- S2-009 已新增 `INVALIDATE_SPECIAL_OUTCOME`：要求原因，从录入事件的前状态精确恢复，保留作废引用并可确定性重放；已通过本地回归，待独立复验。
- S2-004/S2-005 是非阻塞遗留。
- 阶段 3 已建立 `MatchSnapshot` 权威快照、只追加命令事件、幂等结果、版本检查、服务端租约心跳和裁判长原子接管。

- 工作台支持拟首发/拟首接、双打手动换位、物理换边、本机翻转视角和减分预览；翻转视角不产生服务端事件，减分不做算术减分。
- 单一在途锁、非乐观比分和 `UNKNOWN` 原 `commandId` 对账继续成立；离线、失去控制或响应未知时界面保留最后一份已确认状态。
- 本轮已执行结果：定向测试 64/64，`pnpm test` 94/94，Playwright 13/13，lint/typecheck/build 通过，生产启动安全 3/3，知识库同步脚本测试 10/10；375/390/1024 视口和 200% 字体视觉 QA 通过。独立复验仍须单独取证。

## 仍未实现或未验证

- 真机手机/平板、真人裁判完整执裁、局域网长时运行和系统浏览器旋转为未测试；当前证据是 Chromium 的 375/390 手机竖屏、1024 平板横屏和 200% 字体浏览器模拟。
- 真实生产部署、HTTPS、备份恢复和迁移时间戳长期方案仍未验证。
- 三个规则 profile 都是演示配置；尽管场地图实现已按 BWF 条文口径自测，正式赛事仍须老师/组织者正式采纳、确认来源并冻结。
- S2-008、S2-009 和场地图工作台尚未获得独立 Claude 复验结论。

## 当前结论：停在阶段 3 收尾

阶段 3 场地图重构的目标自动化和视觉 QA 已通过，完整收尾仍需最终质量门禁、文档同步与独立复验证据。不把浏览器模拟写成真机验收，不把待采用的 BWF 口径或演示 profile 写成正式规程，不把本地运行写成生产部署。未经用户明确要求不进入阶段 4。

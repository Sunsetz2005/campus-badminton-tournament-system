# 当前进度与下一步

## 当前事实

- 阶段 0 的需求、架构、规则、交互、测试和安全同步文档已完成。
- 阶段 1 的 Next.js/React/TypeScript 工程、PostgreSQL 迁移、Better Auth 登录、服务端角色/指派校验、公开白名单和最小控制会话基础已完成。
- Claude 独立复验判定阶段 1 必需验收通过；后续 S1-010—S1-014 也已全部复验通过。
- 阶段 2 已实现纯 TypeScript 规则引擎：三个演示 profile、抛币、单双打逐分、双打 R/L、发接发、间歇、物理换边、撤销、更正、暂停、特殊结果、提交/确认/重开和确定性重放。
- 规则引擎不读取数据库、网络、当前时间或随机数；命令时间和抛币事实从外部输入。屏幕方向不进入比赛状态。
- Claude 阶段 2 第二轮独立复验判定 S2-002、S2-003、S2-006 通过，S2-001 的替换值校验通过但命令入口阶段门禁缺失，遗留部分另立 S2-007。
- S2-007 第 3 轮独立复验通过：四类更正的结果锁、比分更正 phase 白名单和 `REOPEN_RESULT` 受控重开通路同时成立。
- S2-009 已新增 `INVALIDATE_SPECIAL_OUTCOME`：要求原因，从录入事件的前状态精确恢复，保留作废引用并可确定性重放；已通过本地回归，待独立复验。
- S2-004/S2-005/S2-008 是非阻塞遗留，阶段 3 尚未开始。
- 本轮实际结果：阶段 2 定向 31/31、`pnpm test` 52/52、Playwright 8/8、生产启动门禁 2/2、lint/typecheck/build 通过。
- 开发库 `badminton_tournament_dev` 与测试库 `badminton_tournament_test` 继续分离；自动化数据库测试只连接 `_test` 库。

## 仍未实现或未验证

- 阶段 2 事件当前只存在于纯聚合内，尚未写入 `MatchEvent`、`Game` 或比赛快照数据库事务。
- `commandId` 的数据库唯一性、`expectedVersion`、控制 token、心跳、接管代号和响应丢失恢复属于阶段 3，尚未实现。
- 完整主裁判页面、按钮防误触、服务端确认后显示成功、多设备和断网只读尚未实现。
- 真机手机/平板/局域网、真实生产部署、HTTPS、备份恢复和迁移时间戳长期方案仍未验证。
- 三个规则 profile 都是演示配置；正式赛事仍须老师/组织者采纳、确认来源并冻结。

## 下一步：进入阶段 3

用户已明确要求进入阶段 3。S2-004、S2-005、S2-008 不构成前置条件，S2-009 本地回归通过但不冒充独立复验。阶段 3 按下列顺序执行：

1. 读取阶段 3 提示词和当前纯引擎接口，不复制第二套计分规则。
2. 在数据库事务中执行授权、租约、命令摘要、幂等、版本检查、事件追加和快照更新。
3. 实现心跳、裁判长接管和旧设备失效，再连接主裁判工作台。
4. 用两设备、重复请求、响应丢失和断网场景验证服务器权威性。

不要把本轮纯规则引擎测试描述成完整裁判系统或真实赛事规程验收。

## 实际做了什么

1. 先实测账号格式：向服务器 `POST /api/auth/sign-in/email` 传裸名 `admin` 返回 `400 INVALID_EMAIL`，因此账号采用完整邮箱形式（具体地址只记在服务器配置中）。要让裸名可登录需另加 Better Auth username 插件，属代码范围扩大，本日未做。
2. 数据库原位改名改密：更新 `users.email` 中裁判员一行，并用容器内 `better-auth/crypto` 的 `hashPassword` 重新写入 `accounts` 三条 credential 的 bcrypt 摘要（163 行摘要一致）。注意 `accounts.accountId` 是 text、`users.id` 是 uuid，比较必须写成 `id::text`；第一次语句报错后回滚，没有留下副作用。
3. 明确不重跑整份种子：用户已手测过 `MS-FRESH-001`（现为 `IN_PROGRESS`、版本 20、20 条事件），种子会把它重置回 0:0，所以只做原位更新。
4. 修一处真实的前端缺陷：`src/components/login-form.tsx` 密码框硬编码 `minLength={12}`，浏览器会在前端直接拦下部分合法口令；登录场景不应套用新建密码的长度规则，删除该属性。
5. 服务器侧收尾：root-only 账号配置更新为三账号；改名前后快照 `pre-account-rename-20260922.sql.gz`；重新构建镜像 `campus-badminton-app:20260922-account1` 并只更新 app 容器，数据库容器未重建。
6. 复验：curl 三账号登录与对应页面；浏览器级脚本 `.local/verify-remote-accounts.mjs`（不提交）走真实登录表单、`/board` 渲染，并在裁判工作台真实取得控制权后显式释放。
7. 本日收尾重跑全量 Playwright，确认删除 `minLength` 没有影响登录辅助路径。

### 实现过程中值得记的两点

1. **`loading.tsx` 会让 `notFound()` 拿不到 404 状态。** 赛程页的 Suspense 边界一进入，响应头就已经以 200 发出，
   页面内再 `notFound()` 只能换内容、换不掉状态码。赛事是否存在的判定因此上移到 `[tournamentSlug]/layout.tsx`。
   另外 layout 抛出的 `notFound()` 不会被它自己的同级 `not-found.tsx` 捕获，会冒泡到上一层，边界文件因此放在 `src/app/public/not-found.tsx`。
2. **公开 404 统一文案是隐私要求，不只是省事。** 赛事不存在、赛事是草稿、比赛不存在、比赛未发布、比赛跨赛事，
   全部收敛到同一段文案；区分文案会泄露「内容确实存在但你看不到」。

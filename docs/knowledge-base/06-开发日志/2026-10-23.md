## 改动

- 系统抛币（迁移 `20261020150000_coin_toss_draw`）：
  - `Match` 新增 `coinTossDrawSide / coinTossDrawVersion / coinTossDrawnAt`，CHECK 约束要求三者同时为空或同时有值。
  - `drawCoinToss`（`scoring-command-service.ts`）：在比赛行锁与可串行化事务内复核控制会话（与记分命令同一套 `requireController`），只在「待抛币」相位可用；用 `crypto.randomInt` 决定胜方，按当时比赛版本保存并写审计 `COIN_TOSS_DRAWN`。同一版本重复请求返回同一结果，刷新、网络重试或换设备都不会重抽。
  - `RECORD_COIN_TOSS` 新增服务端校验：本版本已有系统抛币结果时，记录的胜方必须一致（422 `coin_toss_draw_mismatch`）。规则引擎不变，历史事件照常重放；没有系统抛币结果的旧比赛与种子数据不受影响。
  - 裁判长作废抛币会改变比赛版本，旧结果随之失效，可以重新抛；权威状态接口只返回对当前版本有效的结果。
  - 工作台：「开始抛币」→ 金/银两面硬币（A/B 方名）抛起翻转约 1.9 秒停在胜方一面 →「某方赢得抛币」→ 继续录入胜方/负方对发球与场地端的真实选择 →「确认并开始」。系统偏好「减少动态效果」时直接显示结果。浏览器不生成随机数。
- 间歇遮罩：出现间歇待办时，场地画面模糊并居中显示「间歇」、倒计时（归零显示「时间到」并闪烁）、「确认间歇完成」；决胜局 11 分同时需要换边时提示并给出「确认换边」入口；「先看场地」只在本机收起，收起后下方细条可重新打开；平板支持时轻震一次。确认仍发送 `ACKNOWLEDGE_INTERVAL` 并等服务器确认。
- 种子修复：2026-10-20 给平台共用裁判账号补全部赛事角色时先读赛事 ID 再写，会与并发删除测试赛事的测试竞争（外键失败）；改为单条 `INSERT … SELECT … ON CONFLICT DO NOTHING`。
- 测试：端到端用例原先手选抛币胜方，现在用 `tests/support/coin-toss.ts` 在 `_test` 库预置本版本的抽签结果再刷新工作台（与真实抛币后刷新的路径相同）；各用例复位比赛时一并清除抽签结果。

## 赛事管理员指定裁判长（同日第二项）

背景：用户在准备「全赛制大型赛事并发仿真测试」（测试方案 `05-测试验收/全赛制并发仿真-测试方案.md` §0 D-1，该文件在主工作区尚未提交）。仿真只走真实接口、不直接写库，但核实发现：建赛只给创建者 `ADMIN`、给平台共用裁判账号 `REFEREE`，全仓库除种子外没有任何地方写入 `CHIEF_REFEREE`。用接口新建的赛事因此无法复核锁定结果、接管、确认小组名次、排除、人工处置、复核仅结果补录或调整出场名单。用户选择先补这个功能。执行者 Claude；属于已完成功能的调整，不是 prompt-kit 新阶段，阶段 9 仍未开始。

### 改动

- 服务 `src/server/services/chief-referee-service.ts`，全部只允许本赛事 `ADMIN`（`requireManagedTournament(..., ["ADMIN"])`）：
  - `grantChiefReferee`：按 `userId`，或按登录用户名 / 邮箱（不区分大小写）把**已有、启用中**的账号授予本赛事裁判长；`createMany … skipDuplicates` 幂等，已是裁判长返回 `granted: false` 且不重复写审计；首次授予写 `CHIEF_REFEREE_GRANTED`。拒绝平台共用裁判账号（409 `platform_referee_not_allowed`：所有裁判都能登录它，授予后「另一位裁判长独立复核」失去意义）、停用账号（409 `account_disabled`）、不存在的账号（404 `user_not_found`）。管理员可以授予自己。
  - `createChiefRefereeAccount`：为本赛事开通裁判长个人账号（用户名规则同裁判员账号）并授予裁判长；初始口令由系统生成、只在本次响应返回、库里只存哈希，`mustChangePassword=true`、`provisionedForTournamentId` 指向本赛事；审计 `CHIEF_REFEREE_ACCOUNT_CREATED` 不含口令；用户名重复 409 `username_taken`。
  - `revokeChiefReferee`：同一事务删除角色，并把该账号在**本赛事**以 `actingRole=CHIEF_REFEREE` 持有的 `ACTIVE` 控制会话改为 `REVOKED`（`revokedReason=CHIEF_REFEREE_REVOKED`），审计 `CHIEF_REFEREE_REVOKED` 记录被吊销的会话；账号本身、其他角色与其他赛事不受影响；本来不是裁判长时返回 `revoked: false`。
  - 支持一个赛事多位裁判长（结果复核人≠提交人、仅结果补录须补录人以外的裁判长复核）。
- 接口：`POST /api/admin/tournaments/[slug]/chief-referees`（授予已有账号）、`POST .../chief-referees/accounts`（开通，201）、`DELETE .../chief-referees/[userId]`（撤销）。均经 `errorResponse` 返回中文错误，写请求受 `src/proxy.ts` 来源校验。前端 `sendJson` 增加 `DELETE`。
- 管理页：赛事概览新增「裁判长」区（`ChiefRefereesPanel`）：列出裁判长（标注本赛事管理员 / 待首次改口令 / 已停用）、撤销、按用户名或邮箱授予、「把我设为裁判长」、开通新裁判长账号（一次性口令展示复用裁判员账号的组件）；不足两位时提示独立复核需要两位以上。
- 无迁移。

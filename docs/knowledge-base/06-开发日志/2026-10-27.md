# 2026-10-27 开发日志

## 全赛制并发仿真 M5—M6（2026-10-26—10-27）

只运行仿真与只读排查，**没有修改业务代码**。总报告：[全赛制并发仿真-测试报告](../05-测试验收/全赛制并发仿真-测试报告.md)。

- M5（本机 L2 四轮并行）：§6 赛务异常 42 项、§13.2 同出口 IP、§13.9 两种设备模式，见 [M5 记录](../05-测试验收/并发仿真-M5赛务异常记录.md)。第一组被本机睡眠 146 秒打断（判无效后重跑）。
- M6（服务器独立实例）：L3 直连一轮、经与演示站同款 nginx 一轮（同一出口、300 名观众、44 名具名裁判），R1 真实节奏与同种子 C8 对照。演示站与同机其他项目未受影响，压测容器已停止。
- 新增系统发现：SF-05（团体名单揭晓造成选手重叠，整个赛事无法再发布排程）、SF-06（同出口下公开查询按固定窗口集中放行，每分钟开头拖慢裁判记分并出现 `P2028` 500），见[系统发现](../05-测试验收/并发仿真-系统发现.md)。
- 仿真脚本修正：等待期间心跳、推迟时顺延下游比赛、会话峰值只数本次运行、观众只取本赛事比赛、资源采样只列现有容器。

## 系统发现 SF-01—SF-06 与赛务口径实施（2026-10-27，同日）

用户确认口径与顺序后实施。口径、规则出处与逐条实施状态见[赛务口径决定-2026-10-27](../03-竞赛规则/赛务口径决定-2026-10-27.md)第七节，系统发现的处理见[系统发现](../05-测试验收/并发仿真-系统发现.md)。

- **SF 修复**：全部交互式事务改走 `runTransaction`（自动重试）；写冲突、等连接超时（`P2028`）、断库返回 503 + `Retry-After`；公开查询限流改为令牌桶，并加 2 秒共享读缓存（生产默认开启）。
- **赛程**：延误造成的重叠记为警告；发布只拦本次改动涉及的硬冲突；选手在别场进行中时不能开局（409 `player_on_other_court`）；裁判长可把暂停中的比赛转场；第一局结束前可作废本场计分。
- **排名、晋级与退出**：小组排名按 BWF GCR 16.2 / 16.3 逐层比较；WO/RET/DSQ 负方与退出单位自动删除小组成绩；淘汰赛空位以 WO 晋级；裁判长在成绩名次页登记选手退出、取消资格或团体整队退出。
- **团体**：出场名单可声明认输某个小场；认输与退赛按「认输方不再得分」补完比分计入积分榜。
- **报名与裁判**：同一学号只能代表一个单位；自动排班负荷均衡、连续执裁不超过 2 场；共用裁判账号须先填执裁人姓名。
- **数据库**：新增 6 个迁移（`20261027120000`—`20261027120500`），只在测试库执行；开发库与演示库未动。
- **浏览器实测时发现并修复**：本队已声明认输、对方还没交名单时，本队名单表把认输小场显示成「未提交」，改为「认输（名单揭晓后生效）」。
- **测试**：Vitest 501/502（1 项跨文件干扰，单独重跑 20/20；独立复核复跑 500/502，2 项干扰单独重跑通过）、Playwright 110/110（新增退出登记、转场、名单认输三处浏览器实测）、typecheck、build 通过，详见[测试记录](../05-测试验收/测试记录.md)。开发自测，未独立复判。
- **独立复核**：另一会话只读复核，结论为可以提交；提出的 3 条低风险问题（新拖入比赛与进行中比赛重叠只报警告、旧确认名次快照方案、转场不看目标场地后续排定）已当日修复，见[测试记录](../05-测试验收/测试记录.md)。
- **未做**：裁判中立（裁判账号没有单位字段）；比赛详情与成绩册显示执裁人；作废计分后的比赛仍按「已开始」冻结赛程。

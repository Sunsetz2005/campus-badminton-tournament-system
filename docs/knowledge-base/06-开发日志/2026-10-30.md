# 2026-10-30 开发日志

用户同意 2026-10-29 的三项口径，并要求补充确认若干点、给出两份评估、最后全量回归。决定与方案的唯一记录在[赛务口径决定 2026-10-29](../03-竞赛规则/赛务口径决定-2026-10-29.md)。

## 补充确认与修改

- **S-8 占用状态**：实现原本就是「进行中、暂停中算占用；已结束待提交、待复核 / 已锁定不算」，补了逐状态用例。
- **S-8 提示**：改为写明占用场地的比赛编号与状态（进行中 / 暂停中），并提示「如果那场实际已经结束或设备失联，请联系裁判长处理」；接口另返回 `busyMatchStatus`。
- **假占用**：新增两个用例走通「主裁判开局后设备失联 → 裁判长接管 → 暂停后转到空场地」和「→ 裁判长登记特殊结果，比赛转为结束待提交」，两条路径都能腾出原场地，等候的比赛随后开局。
- **未排程就打完的比赛**：验证发现**补发不了**：发布赛程只公开有计划时间的比赛，而已开始比赛的时间与场地被冻结、永远排不上，名次将永远无法发布。已修：`publishSchedule` 同时公开已开打或已有结果的未排程比赛（没打的不公开）；公开赛程把它们列在「未排入赛程」。`results.test.ts` 改为用真实的补发赛程走这条路径。
- **内部草稿**：草稿版原本就标「草稿（含暂定结果，不作为正式成绩）」且只对管理员 / 编排员开放；但它只列已公开的比赛，名次依据缺场。改为草稿另含已开打或已有结果的未公开比赛，并在名次说明里注明「含 N 场尚未公开的比赛，仅内部草稿可见」。
- **排班人手不足**：原来空闲裁判都已连续 2 场时会悄悄让其中一人连续第 3 场，同一时段没人空闲时悄悄留空。现在自动建议返回 `refereeShortage`，页面逐条列出「只能连续执裁第 3 场」「没有空闲裁判、未指派」「没有可分配的具名裁判」的场数。
- **种子并发**：全量 Vitest 一次出现 `seed-auth.test.ts` 失败：种子给平台共用裁判补写各赛事角色时，别的测试文件正好删掉临时赛事，撞外键 23503。种子该步改为遇 23503 重试（最多 5 次）。

# 测试计划

## 分层策略

| 层级 | 工具/方式 | 重点 |
|---|---|---|
| 纯规则单元测试 | Vitest | 单双打逐分、发接发、左右位置、间歇、换边、撤销、特殊结果 |
| 服务端命令测试 | Vitest + 测试数据库 | 鉴权、事务、幂等、版本冲突、租约、审计和影响重算 |
| 组件/交互测试 | Vitest/React 测试工具 | 按钮状态、只读原因、待确认和错误反馈 |
| 浏览器流程测试 | Playwright | 报名到成绩册、主裁判完整执裁、移动视口、多会话 |
| 人工验收 | 手机/平板/电脑和真实操作人 | 可读性、防误触、现场流程和规则确认 |

自动化通过不等于老师认可规程，也不等于真实设备验收通过。每次记录测试环境、命令、通过数和失败项。

- 阶段 2：第三轮独立复验确认 S2-007 通过并允许进入阶段 3；S2-009 已实现并通过本地回归，等待独立复验。
- 阶段 3：权威事务、两设备、重复请求、响应丢失、断网、接管、S2-008 双语义和场地图工作台已通过本地自动化；最新回归为定向 64/64、全 Vitest 94/94、Playwright 13/13、lint/typecheck/build 通过、生产启动安全 3/3、知识库同步脚本测试 10/10。真机、真人裁判、正式规则采用和独立复验仍未完成。

需求补充 v1.0 的 24 组跨阶段场景集中维护在[赛事执行规则 v1.0 验收用例](赛事执行规则-v1.0验收用例.md)。只有已实际执行的层级才能标记本地回归通过；后续阶段、真机/真人和独立复验仍分开记录。

## 七项风险的最低测试

1. 双打使用经裁判审阅的逐分黄金序列，逐分断言六类状态。
2. 撤销覆盖普通分、间歇点、换边点、局结束和比赛结束。
3. 物理换边、逻辑左右更正和屏幕翻转互不污染。
4. 同命令并发发送和超时重试只产生一个事件。
5. 两设备同时写、租约超时、裁判长接管后旧设备写入均有结果。
6. 请求到达但响应丢失、刷新页面和断网恢复不能显示假成功。
7. 更正前后比较排名、晋级、已排赛程和已开始后续比赛。
8. 录入/导入覆盖幂等、重名、固定双打成员和跨项目冲突。
9. 排名覆盖两人直接胜负、三人净胜局/净胜分、抽签持久化和退出统计排除。
10. 报表/公开覆盖服务端白名单、锁定快照、版本替代、动态分页和真实设备边界。

# 黄金用例与回归清单

这里定义必须实现的场景，不表示当前已经通过。正式逐分期望值要由最新适用规程和老师/裁判员复核后固化为测试夹具。

## 规则引擎

- [ ] 单打从 0:0 到 21 分演示局，覆盖双方连续得分和发球权转换。
- [ ] 20:20 延长至两分差以及演示封顶场景。
- [ ] 双打四名固定球员的长逐分序列，逐分断言比分、发球方、发球员、接发球员、双方左右位置。
- [ ] 接发方得分取得发球权时，不机械交换其两名球员。
- [ ] 间歇点、决胜局换边点和局结束只各触发一个待办。
- [ ] 手动合法位置更正后继续逐分，算法从新状态延续。

## 撤销、更正和换边

- [ ] 普通得分后撤销恢复全部关联状态，审计仍含原操作。
- [ ] 间歇点得分后撤销，间歇待办恢复正确。
- [ ] 换边点产生待办、确认一次交换一次、重复命令不再交换。
- [ ] 局结束后撤销，回到进行中并取消不合法的下一局状态。
- [ ] 屏幕翻转不改变 A/B、比分、物理端和发接发。
- [ ] 非最近一分更正要求原因与授权，并显示前后差异。

## 并发和网络

- [ ] 同 `commandId`、同载荷重复提交返回原结果，只产生一次事件。
- [ ] 同 `commandId`、不同载荷明确拒绝。
- [ ] 两设备使用同版本并发加分时仅一方成功，另一方收到冲突。
- [ ] 裁判长接管后，旧设备即使网络恢复也不能写入。
- [ ] 命令已提交但响应丢失时，刷新后查询原 ID，不能重复加分。
- [ ] 断网时所有比赛写操作禁用，恢复后先获取权威状态。

## 业务链和结果影响

- [ ] 单打和双打报名审核后进入正确项目与签表。
- [ ] 场地、参赛者、裁判和休息时间冲突被识别。
- [ ] 小组排名页面展示逐级计算依据。
- [ ] 上游已确认结果更正能预览排名和晋级变化。
- [ ] 后续比赛已开始时普通自动更正被阻止并建立处置记录。
- [ ] 成绩册是真实下载文件，公开页面不含私密字段，导出防公式注入。

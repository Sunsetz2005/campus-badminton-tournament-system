# 黄金用例与回归清单

这里定义必须实现的场景，不表示当前已经通过。正式逐分期望值要由最新适用规程和老师/裁判员复核后固化为测试夹具。

需求补充后的完整编号场景见[赛事执行规则 v1.0 验收用例](赛事执行规则-v1.0验收用例.md)。

## 规则引擎

- [x] 单打从 0:0 开始覆盖双方连续得分、发球权和奇偶发球区转换。
- [x] 20:20 延长至两分差以及 29:29 后 30 分封顶。
- [x] 替代 3×15 在 14:14 延长、20:20 后以 21 封顶；8 分间歇不重复触发。
- [x] 抛币胜方选择先接发球或场地；事件重放不重抽，下一局沿用原抛币记录。
- [x] 双打四名固定球员的逐分序列，逐分断言比分、发球方、发球员、接发球员和双方左右位置。
- [x] 接发方得分取得发球权时，不机械交换其两名球员。
- [x] 间歇点、决胜局换边点和局结束各只产生一个待办。
- [x] 手动合法位置更正后继续逐分，算法从新状态延续。
- [ ] 单打 0:0、1:0、1:1、1:2 分别断言发球方比分奇偶、斜对角 R/L、唯一发球员和唯一接发员。（投影断言已新增，待本轮完整门禁）
- [ ] 双打独立黄金序列逐分断言四格、唯一发球标记和接发员，证明只有发球方得分时该方交换 R/L。（投影断言已新增，待本轮完整门禁）
- [ ] 发球区或发接发顺序更正只纠正规则状态并保留已有比分，之后继续得分不回退到旧位置。（待本轮完整门禁）

## 撤销、更正和换边

- [x] 普通得分后撤销恢复全部关联状态，追加事件仍含原操作。
- [x] 间歇点得分后撤销，间歇待办恢复正确。
- [x] 换边点产生待办、确认一次交换一次、重复命令不再交换。
- [x] 局结束和比赛结束后撤销，回到进行中并恢复胜局数。
- [x] 屏幕翻转不属于比赛命令，规则状态中没有屏幕方向字段。
- [x] 非最近一分更正要求原因与授权，并显示前后差异。
- [ ] `CORRECT_PHYSICAL_ENDS + FULFILL` 使用提交端位并消费所引用的 `CHANGE_ENDS` 待办，不额外交换一次。（实现及定向断言已新增，待本轮完整门禁）
- [ ] `CORRECT_PHYSICAL_ENDS + KEEP_PENDING` 只纠正当前端位并保留所引用的 `CHANGE_ENDS` 待办，随后仍可确认实际换边。（实现及定向断言已新增，待本轮完整门禁）
- [ ] 错误待办 ID、缺失关系、新旧关系字段并存、无待办却附关系及 `PHYSICAL_ENDS_REVIEW + KEEP_PENDING` 均拒绝。（实现及定向断言已新增，待本轮完整门禁）
- [ ] 旧 `fulfillsObligationId` 历史事件经 JSON 往返后仍可重放；新命令只使用 `obligationRelationship`。（实现及定向断言已新增，待本轮完整门禁）
- [ ] `CORRECT_LOGICAL_COURTS`、`CORRECT_SERVICE_ORDER`、`CORRECT_PHYSICAL_ENDS` 的允许/拒绝 phase 矩阵完整覆盖赛前、进行中、待办、暂停、局末、局间、特殊结果、结果待提交、已提交和已确认。（实现及定向断言已新增，待本轮完整门禁）

## 场地图投影与工作台（本轮待完整门禁）

- [ ] `END_1 / END_2 × 正常 / 翻转 × R / L` 全矩阵：正常左 `END_1`、右 `END_2`，翻转后整体旋转 180°；左上 L/左下 R、右上 R/右下 L。
- [ ] `physicalEnds` 唯一决定 A/B 当前屏幕半场；确认换边只移动队伍、球员及其比分面板，`score.A` / `score.B` 数值归属不交换。
- [ ] 双打四人分别进入四格；单打每方只有一个下一球规则发球区有球员，另一格为空。
- [ ] `IN_PROGRESS`、`OBLIGATIONS_PENDING`、`PAUSED` 只显示一个发球标记和一个接发标记；赛前、局间未设置和比赛结束不误标。
- [ ] 首局和下一局可选择非名单第一人的首发、首接；确认前显示“拟首发 / 拟首接”，确认并刷新后保持服务器权威结果。
- [ ] 双打自动换位、手动更正一方换位后继续得分、物理换边和撤销恢复均从权威状态投影，不在组件中复制规则。
- [ ] 单打“核对站位”不产生任意换位，只引导比分或发球方更正。
- [ ] 本机翻转视角不写事件、不改变服务器版本，刷新本设备时按设备偏好恢复。
- [ ] `−` 只打开服务端撤销预览；最近一分不属于被点击方时拒绝确认，取消预览不写事件。
- [ ] 所有写按钮共用单一在途锁；提交中、响应未知、离线、冲突和失控时，比分、站位与发球标记停留在最后确认状态。
- [ ] 响应未知时先按原 `commandId` 查询，查不到也只以原命令重试，不自动创建新 ID。
- [ ] 统一受控抽屉覆盖原因输入和危险确认，验证初始焦点、Escape、键盘确认、错误提示与返回原路径，不出现浏览器原生 `prompt/confirm`。
- [ ] 390×844、375 px 宽、1024×768、200% 字体、纯键盘、`prefers-reduced-motion`、`prefers-reduced-transparency`、高对比模式下核心功能可用。
- [ ] 更新单打/双打手机竖屏和平板横屏截图，并明确标注“Chromium 浏览器设备模拟”；真机和真人裁判另列为未测试。

## 并发和网络

- [x] 同 `commandId`、同载荷重复提交返回原结果，只产生一次事件。
- [x] 同 `commandId`、不同载荷明确拒绝。
- [x] 两设备使用同版本并发加分时仅一方成功，另一方收到冲突。
- [x] 裁判长接管后，旧设备即使网络恢复也不能写入。
- [x] 命令已提交但响应丢失时，刷新后查询原 ID，不能重复加分。
- [x] 断网时所有比赛写操作禁用，恢复后先获取权威状态。

## 业务链和结果影响

- [ ] 手工/批量导入预览新增、重复和错误；重复导入幂等，重名不自动合并。
- [ ] 双打固定两名成员；线下兼项限制不替代跨项目排程/休息冲突检查。
- [ ] 场地、参赛者、裁判和休息时间冲突被识别。
- [ ] 小组排名页面展示逐级计算依据。
- [ ] 小组退出排除该参赛单位及全部相关贡献，但比赛和比分历史仍可查。
- [ ] WO/RET/DSQ/BYE 不伪造 21:0，暂停/待裁决不自动产生胜者。
- [ ] 上游已确认结果更正能预览排名和晋级变化。
- [ ] 后续比赛已开始时普通自动更正被阻止并建立处置记录。
- [ ] 成绩册是真实下载文件，公开页面不含私密字段，导出防公式注入。
- [ ] 正式导出只使用锁定快照并生成新版本；资料包 HTML/PDF 仍标记模拟参考。

## ADR-001：模块化单体和 TypeScript 单语言

**决定**：采用 Next.js + React + TypeScript 的模块化单体，PostgreSQL + Prisma 持久化，Vitest 做规则/单元测试，Playwright 做流程测试。

**理由**：项目规模是单个校园赛事系统，复杂性集中在比赛状态和裁判端可靠性。一个应用、一个数据库和明确模块边界比微服务更容易运行、演示、备份和定位问题。

**后果**：阶段 1 不引入 Redis、消息队列、Kubernetes或付费大模型 API。核心模块按 `rules`、`commands`、`persistence`、`ui`、`reports` 分层；React 点击回调不能直接承载规则判断。

## ADR-003：权威状态、事件和快照

数据库是正式状态来源。每个比赛写命令在同一事务中完成：鉴权 → 租约/接管代号检查 → `expectedVersion` 检查 → `commandId` 幂等检查 → 追加命令/事件 → 计算并保存权威快照 → 版本递增 → 返回确认。

逐分操作采用追加式历史和确定性 reducer。普通撤销追加“撤销目标命令”事件，再重放得到新快照；不物理删除历史，也不直接把总分减一。为了性能可以保存受版本约束的快照，但事件历史仍是审计依据。

## 核心风险及架构控制

| 风险 | 设计控制 | 阶段验收 |
|---|---|---|
| 双打发接发和左右分配错误 | 固定 A/B 与四名球员身份；逻辑发球区使用纯 reducer | 阶段 2 黄金逐分序列 |
| 撤销只改比分 | 追加撤销事件并确定性重放全部关联状态 | 局点、换边点、局结束后撤销 |
| 换边和视角混淆 | `courtEnds`、`logicalCourts`、`screenOrientation` 独立字段/命令 | 各操作互不改变另外两类状态 |
| 重复请求重复加分 | 命令 ID 唯一键 + 规范化载荷摘要 | 同 ID 同内容/不同内容测试 |
| 多设备同时写 | 版本检查 + 写入租约 + 心跳 + 单调接管代号 | 两设备竞争和旧设备阻断 |
| 断网或响应丢失假成功 | 客户端 pending/unknown，原命令 ID 查询或重试 | 丢响应、刷新、恢复连接测试 |
| 更正破坏名次和晋级 | 影响图预览、授权工作流、事务重算和后续状态门禁 | 已排/已开始后续比赛场景 |

## ADR-001：模块化单体和 TypeScript 单语言

**决定**：采用 Next.js + React + TypeScript 的模块化单体，PostgreSQL + Prisma 持久化，Vitest 做规则/单元测试，Playwright 做流程测试。

**理由**：项目规模是单个校园赛事系统，复杂性集中在比赛状态和裁判端可靠性。一个应用、一个数据库和明确模块边界比微服务更容易运行、演示、备份和定位问题。

**后果**：阶段 1 不引入 Redis、消息队列、Kubernetes或付费大模型 API。核心模块按 `rules`、`commands`、`persistence`、`ui`、`reports` 分层；React 点击回调不能直接承载规则判断。

## ADR-006：认证、项目运行时与测试数据库

**决定**：采用 Better Auth 1.7.5 + Prisma adapter 的数据库会话和邮件/密码登录，不自建密码协议。公开注册关闭；测试身份只能由显式本地种子配置创建，生产环境发现示例账号开关或密码变量时拒绝启动。

项目通过 pnpm 的 `devEngines.runtime` 固定 Node 24.21.0。用户全局 Node 26 保持不变，`pnpm exec node`、Prisma、Next、Vitest 和 Playwright 均使用项目 runtime。

开发库固定为 `badminton_tournament_dev`，自动化测试库必须以 `_test` 结尾。测试准备脚本在任何迁移或种子操作前解析并验证数据库名；模拟种子另外只允许开发库或 `_test` 库。

**后果**：登录密码由 Better Auth 使用 scrypt 保存；权限仍在自有服务端 DAL 中按账号状态、赛事角色和具体比赛指派检查。认证库只证明身份和会话，不替代业务授权。

## ADR-003：权威状态、事件和快照

数据库是正式状态来源。每个比赛写命令在同一事务中完成：鉴权 → 租约/接管代号检查 → `expectedVersion` 检查 → `commandId` 幂等检查 → 追加命令/事件 → 计算并保存权威快照 → 版本递增 → 返回确认。

逐分操作采用追加式历史和确定性 reducer。普通撤销追加“撤销目标命令”事件，再重放得到新快照；不物理删除历史，也不直接把总分减一。为了性能可以保存受版本约束的快照，但事件历史仍是审计依据。

## ADR-004：规则继承、发布冻结与模板版本

**决定**：规则采用“赛事默认 → 单项/组别 → 阶段 → 比赛快照”的显式继承链。配置以不可变 revision 保存；抽签发布时冻结阶段选择，每场创建只读 `MatchRuleSnapshot`。修改模板只能产生新 revision，不能更新历史比赛引用。

**最小字段**：`profileId`、`revision`、`scopeType/scopeId`、`sourceLabel`、`sourceVersion`、`effectiveFrom`、`config`、`configHash`、`createdBy`、`frozenAt`、`adoptedBy/adoptedAt`。一个循环小组的比赛必须引用同一阶段 revision。

**后果**：阶段 1 只实现存储、继承解析和模拟比赛快照；三个预设的完整 reducer 在阶段 2 实现。3×15 明确使用替代规则参数 15/赢2/21封顶/8分阈值，不把目标分误作封顶分。

## ADR-005：报名范围和模拟模板隔离

**决定**：V1 报名能力改为后台手工录入和 Excel/CSV 批量导入；公众在线报名、材料审核和自动兼项名额限制后移。运动员内部 ID 是跨五单项冲突检查的唯一连接点，双打组合必须展开两名成员。

资料包的 HTML/PDF/JSON 只作为隔离的模拟参考资产，不进入正式业务数据，不证明公开页、报表或移动端已实现。真实公开和导出必须来自服务端白名单与锁定快照。

## 核心风险及架构控制

| 风险 | 设计控制 | 阶段验收 |
|---|---|---|
| 双打发接发和左右分配错误 | 固定 A/B 与四名球员身份；逻辑发球区使用纯 reducer | 阶段 2 黄金逐分序列 |
| 撤销只改比分 | 追加撤销事件并确定性重放全部关联状态 | 局点、换边点、局结束后撤销 |
| 换边和视角混淆 | `courtEnds`、`logicalCourts`、`screenOrientation` 独立字段/命令 | 各操作互不改变另外两类状态 |
| 重复请求重复加分 | 命令 ID 唯一键 + 规范化载荷摘要 | 同 ID 同内容/不同内容测试 |
| 多设备同时写 | 版本检查 + 写入租约 + 心跳 + 单调接管代号 | 两设备竞争和旧设备阻断 |
| 断网或响应丢失假成功 | 客户端 pending/unknown，原命令 ID 查询或重试 | 丢响应、刷新、恢复连接测试 |
| 更正破坏名次和晋级 | 影响图预览、授权工作流、事务重算和后续状态门禁 | 已排/已开始后续比赛场景 |

## 阶段 1 实际结构

- `src/domain/rules`：纯规则配置与哈希；完整 reducer 尚未实现。
- `src/server/auth`、`src/server/services`：会话、授权、公开查询和最小控制会话。
- `src/db`、`prisma/`：Prisma Client、数据库安全门禁、schema、迁移和种子。
- `src/app`、`src/ui`：Next.js App Router 页面/API 和最小展示组件。
- `src/reports`：公开字段白名单；成绩册生成尚未实现。
- `tests/domain|db|integration|e2e`：分层测试。

阶段 1 没有实现计分 reducer、完整比赛命令、接管、编排、排名或报表。

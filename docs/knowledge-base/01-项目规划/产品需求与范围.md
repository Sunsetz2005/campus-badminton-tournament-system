# 产品需求与范围

## 产品目标

为校内羽毛球赛事提供一套可由体育专业学生理解、操作和验收的系统。所有角色读取同一后端权威数据，主裁判端能够完成真实单双打执裁，而不是只展示静态记分界面。

完整业务链为：赛事设置 → 报名与审核 → 分组和编排 → 赛程与裁判指派 → 临场执裁 → 成绩复核 → 名次和晋级 → 成绩册与公开查询。

## 用户与权限

| 角色 | 核心任务 | 权限边界 |
|---|---|---|
| 赛事管理员 | 创建赛事、配置项目、管理账号和最终发布 | 仍需经过服务端校验和审计 |
| 组织/编排人员 | 审核报名、分组、编排、排场地时间和指派裁判 | 默认不能替代主裁判随意改逐分历史 |
| 临场主裁判员 | 接管本人获授权比赛、记分、换边、提交结果 | 只能写入有效指派且持有租约的比赛 |
| 裁判长/授权负责人 | 复核、接管、批准非普通更正和解锁结果 | 所有特殊操作必须记录原因和影响 |
| 只读公众 | 查询公开赛程、成绩、名次 | 不得看到学号、联系方式、凭据等私密字段 |

隐藏按钮、猜不到 URL 或客户端角色标记都不是授权措施。服务端从认证会话取得操作者身份，再检查角色、赛事、比赛状态、指派和有效写入租约。

## V1 必须包含

- `EVT`：赛事、项目/组别、规则配置和每场规则快照。
- `REG`：个人、双打报名，搭档关系、审核状态和重复/冲突校验。
- `DRAW`：分组、种子和回避约束，循环赛与淘汰赛基础编排，人工调整留痕。
- `SCH`：场地、时间、参赛者和裁判冲突检查，裁判指派。
- `OFF`：主裁判本人比赛列表、接管、抛硬币、开局设置、逐分执裁、间歇、换边、撤销、更正、特殊结果、结果确认。
- `RES`：成绩复核、名次解释、晋级、已确认结果更正的影响控制。
- `RPT`：成绩册、表格/PDF/打印输出和隐私受控的公开查询。
- `REL`：幂等命令、版本冲突、单场写入租约、断网安全、审计和恢复。

主裁判端的详细要求见[裁判端交互规范](../04-交互设计/裁判端交互规范.md)，追踪状态见[需求验收追踪矩阵](需求验收追踪矩阵.md)。

## V1 暂不包含

- 原生 iOS/Android App；使用响应式网页。
- 团体赛、支付、短信、直播、商业化和多租户平台。
- AI 视频判分、动作识别或自动识别球员真实跑位。
- 离线继续记分后自动合并；V1 断网时禁止写入。
- 自动宣称符合“最新规则”；正式规则必须按赛事规程冻结。

## 成功标准

完成 V1 时应能够用一个模拟校园赛事证明：报名数据进入编排，赛程可分配场地和裁判；两台设备读取同一比赛，其中只有当前主记分设备能写；主裁判完成单双打逐分、换边、撤销和结果确认；成绩进入名次与成绩册；更正能够展示对名次和晋级的影响。

阶段 0 的成功标准仅是：需求完整、风险显式、环境真实记录、知识库可安全同步。不能以阶段 0 文档替代上述产品验收。

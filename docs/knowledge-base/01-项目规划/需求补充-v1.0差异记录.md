# 需求补充 v1.0 差异记录

本记录依据 `/Users/a10954/Downloads/badminton-rules-v1` 整理。资料包把内容分为“用户已决定”“有依据的规则”和“项目默认”；项目默认仍须赛事组织者在发布前采纳、公示并冻结，不能写成老师或学校已经批准。

权威业务正文见[赛事执行规则 v1.0](../03-竞赛规则/赛事执行规则-v1.0.md)，新增验收场景见[赛事执行规则 v1.0 验收用例](../05-测试验收/赛事执行规则-v1.0验收用例.md)。

## 与旧需求的差异

| 主题 | 旧需求/占位 | v1.0 决定 | 处理 |
|---|---|---|---|
| 规则配置 | 每场冻结规则快照，但正式计分配置待确认 | 赛事默认 → 单项/组别 → 阶段 → 每场只读快照；抽签发布后冻结 | 补充，不削弱快照原则 |
| 计分预设 | 仅传统 21 分演示；3×15 不启用 | 提供传统 21、替代 3×15、单局 21 三个预设；3×15 为 15/赢2/21封顶/8分阈值 | 替代旧占位，正式赛事仍需采纳 |
| 报名入口 | 个人/双打报名与审核属于 V1 | V1 以管理员手工录入和 Excel/CSV 导入为主；公众在线报名、材料审核、自动兼项名额限制后移 | 范围冲突，以新决定为准 |
| 兼项 | 具体限制待确认 | 限制在线下审核；软件仍必须跨五单项按运动员 ID 检查同时比赛与休息 | 保留并加强排程检查 |
| 双打组合 | 固定两名球员 | 抽签发布后冻结成员，不得靠改姓名换人 | 补充版本与审计要求 |
| 分组 | 循环/淘汰与约束待确认 | 2—5 人/对单循环；6 起小组循环＋淘汰；每组目标 4、允许 3—5；前 2 出线 | 项目默认 |
| 种子 | 待确认 | 默认不自动生成；有依据时手工指定并保存依据，限制上限 | 项目默认 |
| 回避 | 同班/院待确认 | 本院赛默认按代表队 ID 尽量回避；属于软约束，失败须解释 | 项目默认 |
| 晋级 | 具体映射待确认 | 固定 2 组/4 组映射；其他组数使用 2 次幂签位，轮空优先小组第一；不设最好第三 | 项目默认 |
| 小组同分 | 不启用正式自动排名 | 胜场 → 两人直接胜负；三人及以上比全组净胜局、净胜分，缩至两人回到直接胜负，仍同则保存抽签 | 采用 S3 第 16.2 逻辑 |
| 异常结果 | 只列类型，不推导 | NORMAL/WO/RET/DSQ/SUSPENDED/ABANDONED/BYE 分开；不补 21:0 | 替代旧占位 |
| 小组退出 | 待确认 | 未完成全部小组赛时，相关全部对阵贡献排除统计但历史保留 | 采用 S3 16.2.5 思路 |
| 休息 | 待确认 | 默认 60 分钟；裁判长逐次批准可缩至 30—59；不足 30 仍拒绝 | 项目默认，参考 S3 11.4 |
| 抛硬币 | 记录胜方及选择 | 胜方可选先发、先接或场地；无效结果可重做，有效确认后禁止刷新重抽 | 补充“先接”和修正流程 |
| 权限 | 五类角色原则 | 管理员不因身份自动能改分；裁判长接管后旧会话立刻失效 | 细化权限矩阵 |
| 成绩锁定 | 结果确认后普通裁判不可回写 | 结束待提交 → 主裁判提交 → 裁判长复核锁定；修订新增版本而非覆盖 | 补充版本链 |
| 公开字段 | 白名单原则，具体字段待确认 | 给出默认公开/禁公开清单；姓名仍由赛事发布决定 | 项目默认 |
| 成绩册 | 真实下载和打印待实现 | 资料包提供静态 HTML/PDF 视觉样例；明确不等于系统功能或校方模板 | 参考资产，不改变实现状态 |

## 阶段 1 最小设计增量

阶段 1 仍只建骨架、数据库、登录权限和模拟比赛，不实现完整编排/裁判 UI。最小补充：

1. 建立可版本化的 `RuleProfileRevision`、继承作用域和不可变 `MatchRuleSnapshot`，先能保存一个模拟比赛的规则快照。
2. 将 `Match.lifecycleStatus`、`outcomeType`、`verificationStatus` 分开，避免一个状态字段混用。
3. 建立 `Participant`、`Entry`、`PairMember` 的唯一身份和双打成员约束，为后续导入/冲突检查留接口；阶段 1 不做完整 Excel UI。
4. 建立 `User`、`RoleAssignment`、`OfficialAssignment` 和 `MatchLease` 的最小权限骨架；管理员不能自动取得记分权。
5. 预留 `ResultRevision` 和 `PublicationSnapshot` 的关系与版本字段，完整更正/发布流程在后续阶段实现。

详细迁移边界见[数据库与实体关系](../02-架构设计/数据库与实体关系.md)。

## 后续阶段顺序变化

- 阶段 1：只补上述基础结构和权限，不抢跑完整排名或报表。
- 阶段 2：计分预设、抛币先接、双打发接发、间歇/换边与撤销。
- 阶段 3：裁判端、单写会话、接管、提交/复核和离线安全。
- 阶段 4—6：后台录入/导入、分组、晋级、排程、异常结果与排名。
- 阶段 7—8：服务端公开白名单、成绩册、响应式及可靠性验收。

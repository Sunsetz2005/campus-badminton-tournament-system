# 规则来源与版本

## 规则配置要求

每个规则配置必须保存：`profileId`、版本、名称、来源、适用范围、核验状态、确认人/时间、参数和变更说明。比赛开始前生成不可变 `RuleSnapshot`；修改默认规则不追溯改变已经开始的比赛。

核验状态固定为：

- `DEMO`：工程演示，不能用于正式认定。
- `PENDING_REVIEW`：有资料但条文或赛事适用性未完整确认。
- `EVENT_APPROVED`：老师/组织者已明确确认用于某赛事。
- `RETIRED`：不再用于新比赛，历史比赛仍保留快照。

## 当前资料状态

| 来源 | 可支持的结论 | 不能支持的结论 |
|---|---|---|
| [BWF Statutes 官方入口](https://corporate.bwfbadminton.com/statutes/) | 正式核验应从此处取得适用版本 | 本轮未稳定取得完整最新版 Laws PDF，不能声称逐条核验 |
| [USA Badminton 2026-04-28 公告](https://usabadminton.org/bwf-approves-3x15-scoring-system/) | BWF 已通过 3×15，公告称 2027-01-04 生效 | 不能据此补齐所有局间、封顶、换边和赛事过渡条文 |
| [Badminton Canada 规则入口](https://www.badminton.ca/page/27820/Rules-of-the-Game)及旧版 PDF | 可作为传统计分、抛硬币、换边和双打条文的历史开发基线 | 不能称为 2026 最新正式规则 |
| 本赛事规程/老师确认 | 决定小组排名、弃权、种子、休息和公开字段 | 当前尚未提供，全部保留为待确认 |

## 传统 21 分制演示规则

建议标识：`traditional-21-demo-v1`，状态 `DEMO`。

| 参数 | 演示值 | 备注 |
|---|---:|---|
| 每场胜局数 | 三局两胜 | 可配置 |
| 每局目标分 | 21 | 历史传统基线 |
| 胜出分差 | 2 | 达到封顶前适用 |
| 封顶分 | 30 | 演示参数，正式赛事前复核 |
| 局中间歇触发 | 领先方 11 分 | 时长待赛事确认 |
| 决胜局换边触发 | 领先方 11 分 | 正式赛事前复核 |

参数必须集中在规则配置中，页面和 reducer 不允许散落 `21`、`30`、`11` 等魔法数字。

## 3×15 的处理

阶段 0 只登记来源和生效公告，不创建可启用的正式 3×15 profile。待获得完整条文后，应逐项确认每局目标、延长/封顶、局中间歇、决胜局换边、赛事过渡和特殊结果，再建立新 profile 和黄金测试。系统不得根据日历日期自动改变一场已创建比赛的规则。

## 正式采用流程

1. 保存原始规程文件或稳定链接、发布日期和适用赛事。
2. 将条文映射为规则参数及不可参数化约束。
3. 由老师/赛事负责人确认赛事本地规则和冲突优先级。
4. 增加逐分、局点、封顶、换边和特殊结果测试。
5. 测试通过后将 profile 标为 `EVENT_APPROVED`，并记录确认人和时间。

待确认清单见[待老师确认的问题](../01-项目规划/待老师确认的问题.md)。

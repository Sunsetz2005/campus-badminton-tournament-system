# 赛事执行规则与产品决策 v1.0

> [!warning] 适用边界
> 本文是可供开发的项目默认方案，不是华南师范大学已发布规程，也不是整套 BWF 最新规则的转载。用户决定的需求可直接用于产品设计；项目默认必须由赛事组织者在发布前采纳、公示并冻结。

## 决策来源和优先级

- **用户已决定**：创建时配置局数/分数；支持男单、女单、男双、女双、混双；报名资格与兼项数量线下审核；V1 以后台录入/批量导入为主。
- **规则参考**：S1 用于计分与执裁，S2 用于替代 3×15 和单局 21，S3 特定条款用于小组排名、退出统计和休息参考。
- **项目默认**：分组规模、种子上限、代表队回避、晋级映射、迟到、权限、锁定修订、公开字段和模板版式。
- **安全约束保持不变**：服务端授权、分阶段开发、命令幂等、单写会话、真实测试、审计和 Obsidian 冲突保护继续有效。

## 五单项与名册录入

独立管理 MS 男单、WS 女单、MD 男双、WD 女双、XD 混双，并允许在单项下设置比赛组别。

V1 使用管理员手工录入和 Excel/CSV 批量导入。公众在线报名、在线资格材料审核、支付和自动兼项名额限制移到后续版本。最小数据包含内部运动员 ID、显示姓名、资格类别、代表队/单位、项目和组别；双打还要有固定组合 ID 和两个不同成员 ID。

导入必须预览新增、重复和错误；重复导入不得重复建人。重名人员不能按姓名自动合并，混双资格不能由姓名、照片或身份证推断。同一单项/组别不得重复报名或加入两个组合。

兼项数量虽然线下审核，排程仍按内部运动员 ID 跨所有项目检查重叠和休息。双打按四名成员展开。双打成员在抽签发布时冻结，发布后不得通过改姓名替换球员。

## 规则层次、冻结和三个预设

规则继承顺序：赛事默认 → 单项/组别覆盖 → 阶段覆盖 → 每场不可变快照。小组赛可单局、淘汰赛可三局，但一个循环小组内必须采用相同配置；阶段设置在抽签发布前冻结，开赛后不随日期、升级或全局修改漂移。

版本至少保存：`profileId`、`version`、`sourceLabel`、`sourceVersion`、`effectiveFrom`、`createdBy`、`frozenAt`、`configHash` 和赛事采用记录。

| 预设 | 局数 | 目标/分差/封顶 | 局中间歇 | 局间间歇 | 换边 |
|---|---|---|---|---|---|
| 传统 21 分 | 三局两胜 | 21 / 2 / 30 | 每局领先方首次 11 分，最多 60 秒 | 最多 120 秒 | 局间；决胜局领先方首次 11 分 |
| 替代 3×15 | 三局两胜 | 15 / 2 / 21 | 每局领先方首次 8 分，最多 60 秒 | 最多 120 秒 | 局间；决胜局领先方首次 8 分 |
| 单局 21 分 | 一局定胜负 | 21 / 2 / 30 | 领先方首次 11 分，最多 60 秒 | 无 | 本局领先方首次 11 分 |

3×15 不是 15 分封顶；它来自 S2 替代规则，不能自动冒称未来完整新规则。偏离预设的配置标为“自定义校内规程”并展示差异。

服务端校验：最多局数为支持的奇数；胜局数为 `(maxGames + 1) / 2`；目标分大于 0；封顶不低于目标；启用阈值大于 0 且低于目标；间歇秒数非负；无效局间节点不能保存。间歇和换边阈值每局只触发一次待确认事项。

## 分组、种子、回避和晋级

- 0 人/对不建赛程；1 人/对只保留报名记录，不自动发冠军。
- 2—5 人/对默认单循环并直接产生最终排名。
- 6 人/对及以上默认小组单循环＋淘汰；每组目标 4，允许 3—5，组间人数差不超过 1；每组前 2 出线。
- 第一版不比较不同小组的“最好第三名”。默认安排三四名赛；关闭时显示并列第三，不虚构第四。
- 未进行 5—8 名排位赛时，不按跨组净胜分硬排 5—8；只显示“八强/并列第五”或“小组未出线”等真实阶段结果。

默认不自动产生种子。有上届同项目成绩或组委会依据时手工指定并保存依据。建议上限：8—15 最多 2 个，16—31 最多 4 个，32—63 最多 8 个，64 以上 V1 最多 16 个；小组赛最多每组 1 个。

本院赛事默认按代表队 ID 尽量回避，而不是对所有人使用“同校回避”。回避是软约束，优先级为：不漏不重 → 人数均衡 → 种子分区 → 尽量减少同单位同组。无法满足时列出具体冲突，禁止悄悄降级。

两组半决赛固定 A1—B2、B1—A2。四组固定 QF1=A1—B2、QF2=C1—D2、QF3=B1—A2、QF4=D1—C2，保证同组出线者分处不同半区。其他组数使用不小于晋级人数的最小 2 次幂签位；轮空优先小组第一，同条件公开随机，不跨组比较净胜分。

抽签发布保存名单快照、种子/回避设置、算法版本、随机结果或可重放参数、操作者和版本。刷新只读已保存结果。发布后只有项目未开赛且存在漏报、错报或明确算法错误时，才可经裁判长批准重抽。

## 小组排名

所有异常处理完成前只显示临时排名。最终排序：

1. 先按全部有效小组比赛胜场。
2. 恰好两人/对并列时看直接胜负。
3. 三人/对及以上并列时，比较整个小组有效比赛净胜局。
4. 分层后只剩两人/对并列，回到直接胜负；仍有三人/对及以上则比较整个小组有效比赛净胜分。
5. 净胜分后只剩两人/对并列，再看直接胜负；三人/对及以上完全相同，由裁判长组织并保存抽签结果。

不得改成并列者“小循环”、得失分比例、报名时间、数据库 ID、拼音或种子顺位。输出有效场次、胜负、局分、净胜局、得失分、净胜分、名次、晋级状态和解释依据。

## 异常结果、退出、迟到和休息

| 结局 | 规则 |
|---|---|
| `NORMAL` | 正常逐局比分决定胜者 |
| `WO` | 开赛前弃权/未到，经裁判长确认；未打局留空，不补 21:0 或 2:0 |
| `RET` | 开赛后退赛，保留实际比分和已完成局，不补满未完成局 |
| `DSQ` | 裁判长确认并记录作用范围；不由超时脚本自动判定 |
| `SUSPENDED` | 保存比分、发接发和位置，没有正式胜者，恢复后接续 |
| `ABANDONED` | 无法恢复、待裁决；不自动把领先方判胜 |
| `BYE` | 只推进签位，不计为实际比赛 |

小组阶段某人/对因 WO、RET、DSQ 或退赛不能完成全部比赛时，从最终排名统计中排除该单位及其全部对阵贡献；原比分、事件和审计仍保留。其他参赛者的胜场、局分和得失分也同步排除对应对阵。已完成全部小组赛后才退出淘汰阶段的，不回溯删除小组成绩。

默认提前 10 分钟检录；场地、对手、裁判和休息条件就绪后记录有效叫场，5 分钟未到只提醒裁判长，不自动判负。

默认两场实际结束到实际开始至少 60 分钟。裁判长可逐次批准 30—59 分钟例外，低于 30 分钟仍拒绝。跨全部项目按运动员 ID 检查，双打取四名成员最晚允许时间；WO/BYE 不产生虚假运动负荷起点，RET 按实际结束时间计算。

## 抛硬币、发接发和纠错

抛币胜方可以选择先发球、先接发球，或选择起始场地；负方选择剩余维度。流程为：确认双方 → 记录胜方 → 胜方选类别和具体选项 → 负方选剩余类别 → 确认首发、首接和场地 → 开赛。

没有明确有效结果时可记录无效后重做。已经有效确认后，刷新、重连或不满意都不能重抽；录入错误优先修正记录。第一球前确需作废须裁判长批准，第一球后不提供普通重抽按钮。

后续局不重新抛币。上一局胜方先发；双打可重新确认该方首发球员和对方首接球员。

自动换位只维护规则上的发接发顺序和左右发球区，不追踪战术跑位。撤销误点、计分更正、发球区纠错、物理换边和屏幕翻转是独立命令。现实已经换边后再撤销误分时进入场地待核对，不把界面重放等同于运动员已经换回。

## 权限、单写会话和成绩锁定

- 主裁判只能操作本人指派且持有有效写会话的比赛；可以正常记分、撤销最近误点和留痕纠正位置。
- WO/RET/DSQ 最终确认、强制接管、成绩复核、解锁和追溯修订属于裁判长。
- 管理员/编排员维护赛事、名单、签表和发布，但不能仅凭管理员身份直接执裁或改分。
- 一人可兼任多角色，但每次敏感操作记录实际身份和所用角色，不能伪造两人独立审核。

一场比赛同一时刻只有一个有效写会话。每条命令带 `commandId`、预期版本和会话代次；重复请求返回原结果。裁判长接管时原子提高代次，旧设备即使离线恢复也不能再写。V1 离线时禁写，恢复后先拉取权威状态。

成绩状态：进行中 → 比赛结束待提交 → 主裁判已提交待复核 → 裁判长复核锁定。只有已锁定且无争议的结果进入正式排名、晋级和最终成绩册。

锁定后更正新增修订版本，不覆盖原记录。影响晋级且后续未开始时先冻结、预览、批准再更新；后续已经开始或结束时禁止自动换人、抹分或覆盖历史，由裁判长决定暂停、维持、取消或重赛。旧成绩册保留并标记被替代。

## 公开字段和成绩册

公开接口采用服务端白名单，可包含赛事、项目/组别、公开编号、获准公开的姓名/代表队、对阵、场地、时间、逐局比分、结局、临时/正式状态、正式名次、版本和更新时间。

默认不公开学号、身份证、电话、邮箱、生日、住址、内部 ID/会话、医疗细节、私密备注和原始审计。姓名未获赛事发布决定时只显示编号或别名。公开网页和公开版 PDF/Excel 共用同一白名单。

资料包中的 7 页 PDF、成绩册 HTML、公开查询 HTML 和 JSON 全是模拟模板：只有版式、本地筛选和模拟数据，没有后台、权限、真实记分、排名引擎或正式发布。详细边界见[成绩册与公开查询模板说明](../08-成果材料/成绩册与公开查询模板说明.md)。

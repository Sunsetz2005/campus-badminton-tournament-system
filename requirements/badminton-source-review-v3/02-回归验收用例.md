# 原项目回归验收清单 V3

基线：84a159218b300de333e101da5af6ea8d51d3bacb。
此表描述应该验证的行为，不表示本轮已在完整项目运行通过。提取复现输出单列于 evidence/。

## 1. 阈值与真实换边

| 用例 | 预期 |
|---|---|
| 单局21，11:0处理间歇和换边，B得分到11:1 | 无重复间歇/换边；实际端保持首次确认后的值 |
| 三局21第一局，11:0处理间歇，到11:1 | 无重复间歇，不产生决胜局换边 |
| 三局21第三局，11:0处理两项待办，到11:1 | 无重复待办，不能再次自动/误提示换回 |
| 3×15第三局，8:0处理两项待办，到8:1 | 同上，阈值来自配置 |
| 一方过阈值后，另一方后来达到阈值 | 不产生第二次局中义务 |
| 换成B方先达到阈值 | 对称正确 |
| 自定义间歇阈值与换边阈值不同 | 分别首次触发、确认、消费，不互相错误抑制 |
| 阈值一分误点、尚未实际换边便撤销 | 恢复正确逻辑和必要待办，不增加虚假确认 |
| 阈值后已实际换边，再撤销触发得分 | 保留物理事实并进入明确核对，不无声换回 |
| 完整比分更正到阈值前、阈值、阈值后 | 义务依据更正与历史事实，不能只看等值判断 |
| 用原始历史事件重放 | 与对应版本状态一致；升级兼容有明确测试 |

## 3. 请求未知与存储

| 注入过程 | 预期 |
|---|---|
| 服务器落库后代理返回502/504 | 保留原commandId并对账，不创建新ID再加一次 |
| 服务器未落库而请求超时 | 查原命令；按有证据的策略安全重试/恢复 |
| 返回200但JSON无效、state缺失或commandId不符 | 不清pending，不标成功 |
| 明确结构化业务拒绝 | 可解释地退出该失败请求，不误当成功或永久锁死 |
| local/session storage损坏、读取/写入失败 | 不崩溃，不丢失未确认操作后假成功，受控恢复 |
| 两标签页、切换用户、旧控制会话失效 | 不混用令牌/未决命令，不让旧设备提交 |

## 4. 时刻与结果

比赛10:00结束→10:05主裁判提交→10:10裁判长复核，实际endedAt仍是10:00；其余两个时间独立记录。对终场误点撤销、退回更正、恢复后再次结束单独断言。没有实际比赛的WO/BYE不能产生假造的开始/结束时长。

## 5. 保留单双打与投影正确性

沿用现有双打逐分黄金轨迹，再覆盖两方首发、不同首发首接人、手动交换本方两人、得分后继续服务、更正后刷新、物理换边和本机翻视角。每一步断言playerId、side、logicalCourt、screen位置、server/receiver与加分目标，而不只检查文本分数。

单打反例：A4分、B3分且B发球时，双方对应的服务区域均应依据B的奇数分；不能按A4分把接发者放入错误区域。

## 6. 界面与设备

实际截图使用CSS视口390×844、1024×768、820×1180、1440×1000。手机和双打长姓名都要看到完整人物身份、服务器状态和可触及的操作。

场地在上，三个换位/换边按钮位于场地之下，再大比分和加减分。常用操作不应被冗长日志挤出主要操作区；异常状态不隐藏。实际换边与仅翻视角各只有明确且不同的语义。

检测非安全上下文缺少crypto.randomUUID的表现，测试提示/只读及部署说明。只有真正连接物理手机或平板完成的步骤才能称为真机验证。

## 7. 验收记录格式

每条记录：用例ID、当前commit、测试类型、执行命令、环境/隔离数据库、预期、实际、状态、证据路径。状态只能是“通过／失败／未验证／不适用”。

提取脚本的四个结果是“重现基线缺陷”，不是“修复通过”。仓库旧报告的通过数是历史数据，不复制成新一轮结果。

# 阶段 4-C 赛程与裁判排班界面证据

由 `tests/e2e/schedule.spec.ts` 在本机生成（Playwright Chromium，`baseURL=http://127.0.0.1:3100`，数据库 `badminton_tournament_test`）。

- 固化命令：`PHASE4C_SHOT_DIR=shots pnpm run test:e2e`（本次随全量 Playwright 一起生成）；普通运行默认写入未提交的 `local-run/`，不改写 `shots/`。
- 截图时只隐藏 `.skip-link`；产品样式未改。
- 数据全部是测试运行中现场创建的模拟赛事（4 个模拟学院、「学院简称＋性别＋序号」占位姓名），测试结束后删除；账号为本地模拟身份。
- 赛事名为「阳光体育羽毛球联赛 赛程端到端」（模拟），2 块场地、1 个比赛日、1 名裁判员，因此建议结果里有一半比赛「尚未指派裁判」（警告，需确认后发布）。

## 文件（`shots/`）

| 文件 | 视口 | 内容 |
|---|---|---|
| 01-settings | 1280×900 | 场地与时段：预计时长、换场时间、淘汰赛每场对抗占用场地数、名单截止提前量；追加 2 块场地；比赛日 |
| 02-draft-suggested | 1280×900 | 生成排程建议后的草稿：单循环一组两块场地同时开打，每场对抗 5 个小场同一场地连打，后续小场标「约」 |
| 03-manual-conflict-mobile | 390×844 | 手机上逐场调整：把一个小场挪到另一场的场地与时间，保存即复检出「同一场地时间重叠」硬冲突 |
| 04-my-assignments-mobile | 390×844 | 发布后裁判的「我的执裁」：新赛事的小场带计划时间、场地与小场类型（上方为阶段 1 演示赛事的既有比赛） |
| 05-workbench-from-schedule-mobile | 390×844 | 从「我的执裁」进入该小场的执裁台（双方出场名单已由管理员代交） |
| 06-chief-board | 1280×900 | 裁判长现场看板：已发布赛程按日期与时间排列、待开赛状态、临时更换裁判入口 |
| 07-public-schedule | 1280×900 | 赛事公开后，公开赛程显示已排定的小场；接上一场之后的时间显示为「预计」 |

校验：`cd shots && shasum -a 256 -c SHA256SUMS`。这些是浏览器模拟截图，不是真机验收，也不是真实组织者或裁判的试用。
